작성일: 2026-09-17  
작업 브랜치: `refactor/minihome-v2`  
기준 커밋: `78159f7 Add admin deletion and YouTube playlist`

## 1. 리팩토링 목표

기존 미니홈피의 기능과 데이터를 유지하면서 코드 구조, 화면 구성, 권한 처리, 검사 과정을 더 이해하기 쉽고 안전하게 정리합니다. 기존 `main`과 공개 사이트는 비교 기준으로 보존합니다.

## 2. 과제 원문에서 확인한 핵심 원칙

출처: `Agentic AI 입문 2-2. AI 리터러시, 논리적 사고.pdf`의 **3. 나만의 미니홈피 만들기**(86~100쪽)

- 디자인보다 필요한 기능을 모두 충족하는 것이 우선입니다.
- `PRD 생성 → Plan으로 계획 → 실행` 순서로 진행합니다.
- 전체 흐름은 `기획 → 첫 화면 → 기능 추가 → 직접 확인 → 공유`입니다.
- 각 단계에서 결과를 확인한 뒤 다음 작업으로 넘어갑니다.
- 문제가 있으면 기능 추가 단계와 직접 확인 단계를 반복합니다.

## 3. 공식 필수 요구사항

| 번호 | 요구사항 | 리팩토링 확인 방법 |
|---|---|---|
| A1 | 프로필, 짧은 소개, 다이어리 글 2개, 방명록 자리가 한 페이지에 표시됨 | 데스크톱·모바일 미리보기 |
| A2 | 공개 가능한 정보만 사용함 | 화면 문구와 저장 데이터 검토 |
| A3 | 모바일에서도 읽을 수 있음 | 좁은 화면에서 가로 잘림과 글자 겹침 확인 |
| A4 | 방명록 닉네임과 메시지가 필수임 | 빈 값 제출 차단 확인 |
| A5 | 작성한 방명록 글이 목록에 표시됨 | 정상 작성 후 목록 확인 |
| A6 | 새로고침 후에도 글이 유지됨 | 작성 후 새로고침 |
| A7 | 다른 기기에서도 같은 글이 표시됨 | 별도 브라우저 또는 비로그인 환경 확인 |
| A8 | 최근 작성 글이 위에 표시됨 | 여러 글의 정렬 순서 확인 |
| A9 | 닉네임은 20자, 메시지는 200자로 제한됨 | 경계값과 초과값 검사 |
| A10 | 성공 또는 실패 결과를 사용자가 알 수 있음 | 안내 문구와 오류 상태 확인 |
| A11 | 기존 방명록 글이 유지됨 | 리팩토링 전후 데이터 비교 |
| A12 | Sites로 배포하고 누구나 접속할 수 있음 | 최종 단계에서 시크릿 창으로 확인 |
| A13 | 공개 페이지에서 방명록을 작성하고 새로고침해도 유지됨 | 배포 뒤 최종 통합 검사 |

## 4. 기존 프로젝트의 추가 기능

다음은 공식 핵심 요구사항이 아니라 기존 제작 과정에서 추가한 기능입니다. 핵심 요구사항을 먼저 통과한 뒤 회귀 검사합니다. 회귀 검사는 예전에 되던 기능이 리팩토링 뒤에도 그대로 되는지 확인하는 검사입니다.

- 알프스 배경 7장의 날짜별 변경
- 명언 30개의 날짜별 변경
- 최근 7일 방문자 그래프
- 관리자 로그인과 비밀번호 변경
- 관리자 전용 다이어리 작성·수정·삭제와 사진 첨부
- 관리자 전용 방명록 수정·삭제
- 요즘의 관심사 수정
- 유튜브 링크 기반 플레이리스트 변경

## 5. 워크트리 운영 규칙

```text
site/                         main · 기존 기준점 · 비교 중심
site-refactor-minihome-v2/   refactor/minihome-v2 · 실제 개선 작업
```

- `site` 폴더에서는 리팩토링 코드를 수정하지 않습니다.
- 새 코드는 `site-refactor-minihome-v2`에서만 수정합니다.
- 작업 묶음마다 검사한 뒤 의미가 드러나는 커밋을 남깁니다.
- 로컬 완성, 브랜치 병합, 공개 배포를 서로 다른 단계로 구분합니다.
- 사용자 확인 전에는 `main`에 병합하거나 공개 사이트를 배포하지 않습니다.

## 6. 구현 순서

### 1단계. 현재 구조와 데이터 흐름 조사

- 화면 구성요소와 파일 역할을 정리합니다.
- 방명록, 다이어리, 관리자 인증, 방문 집계의 데이터 흐름을 확인합니다.
- 기존 동작과 데이터를 기준 자료로 기록합니다.

완료 조건: 주요 기능마다 관련 파일, 데이터 저장 위치, 검사 방법이 연결됩니다.

### 2단계. 화면 구조 정리

- 프로필, 소개, 다이어리, 방명록을 역할별 구성요소로 분리합니다.
- 공통 스타일과 모바일 배치를 정리합니다.
- 기존 화면과 개선 화면을 같은 크기에서 비교합니다.

완료 조건: 공식 요구사항 A1~A3을 통과합니다.

### 3단계. 방명록 흐름 정리

- 입력 검사, 저장 요청, 성공·실패 안내, 목록 갱신을 분리합니다.
- 기존 글 유지와 최신순 정렬을 확인합니다.
- 방문자 기능과 관리자 수정·삭제 권한을 구분합니다.

완료 조건: 공식 요구사항 A4~A11을 통과합니다.

### 4단계. 다이어리와 관리자 기능 정리

- 관리자 인증과 보호된 작업의 경계를 확인합니다.
- 다이어리 작성·수정·삭제·사진 첨부 흐름을 정리합니다.
- 잘못된 비밀번호와 비로그인 요청이 차단되는지 확인합니다.

완료 조건: 일반 방문자가 관리자 기능을 실행할 수 없고 기존 데이터가 유지됩니다.

### 5단계. 부가 기능 회귀 검사

- 날짜별 배경과 명언, 방문 그래프, 관심사, 플레이리스트를 확인합니다.
- 모바일 화면과 오류 안내를 함께 점검합니다.

완료 조건: 기존 추가 기능의 정상 동작 여부가 항목별로 기록됩니다.

### 6단계. 전후 비교와 제출 문서 작성

- 기존본과 개선본의 화면·구조·검사 결과를 비교합니다.
- 처음 제작한 워크플로우, 새 워크플로우, 달라진 점을 문서화합니다.
- 최종 제출용 PDF를 만들고 화면을 확인합니다.

완료 조건: 요구사항, 구현, 검사 증거가 서로 연결된 PDF가 완성됩니다.

### 7단계. 병합과 배포 판단

- 사용자 확인 뒤에만 `main` 병합 여부를 결정합니다.
- 배포 요청이 있을 때만 공개 사이트를 갱신합니다.
- 배포한 경우 공식 요구사항 A12~A13을 시크릿 창에서 확인합니다.
