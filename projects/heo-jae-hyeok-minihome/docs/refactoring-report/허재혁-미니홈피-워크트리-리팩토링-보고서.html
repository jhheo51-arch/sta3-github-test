01 · Refactoring Goal

안정적으로 쓰고, 다음에도 안전하게 수정하기 위해

1차 정리와 추가로 발견한 문제

  • 1차에는 화면과 공통 처리의 역할을 분리하고 중복 함수를 정리했습니다.
  • 방명록의 잘못된 입력과 저장 실패가 일관되게 처리되지 않았습니다.
  • 유튜브 주소 해석이 잘못된 프로토콜과 영상 ID를 허용했습니다.

이번 리팩토링 목표

정상적인 글 작성과 음악 설정은 유지하면서,
잘못된 입력을 차단하고 실패 원인을 일관되게 알려줍니다.
공통 규칙과 반복 검사로 다음 수정의 오류 위험을 줄입니다.

기존 기능과 사용자 데이터 유지
입력 검증과 실패 응답의 일관성 확보
반복 검사로 변경 안전성 확인

실패 처리

입력 오류와 저장 실패를 구분해상황에 맞는 안내를 반환합니다.

공통화

화면과 저장 API가 같은 유튜브 주소 검증 함수를 사용합니다.

반복 검사

같은 검사 명령을 다시 실행해 기능이 유지되는지 확인합니다.

성공 기준

유지

정상 입력·관리자 인증·저장 구조를 유지합니다.

일관성

화면과 저장 단계에서 같은 링크 규칙을 적용합니다.

실패

잘못된 입력은 거부하고 저장 실패는 성공으로 알리지 않습니다.

04 · Implementation Results

개선 전: 경계값과 실패에 빈틈

방명록의 잘못된 JSON이 서버 오류로 처리되고,
수정·삭제의 실패 안내가 일관되지 않았습니다.

유튜브 해석은 잘못된 프로토콜이나 영상 ID도 받아
화면과 저장 단계의 판단이 달라질 수 있었습니다.

개선 후: 한 곳에서 일관되게 검사

방명록 작성·수정·삭제의 공통 검사를 모으고,
입력 오류·권한 없음·글 없음·서버 실패를 구분했습니다.

유튜브 주소는 공통 함수에서 형식과 영상 ID를 검사해
화면과 저장 API가 같은 규칙을 쓰게 했습니다.

방명록 실패 안내

잘못된 입력과 저장 실패를 구분하고,
저장 결과가 없으면 성공을 반환하지 않습니다.

음악 설정의 일관성

화면과 저장 처리의 검증을 통일해,
잘못된 형식의 링크가 통과하지 않게 했습니다.

다음 수정의 안전성

정상·오류·권한 사례를 다시 실행해,
기존 동작이 깨지는지 확인할 수 있습니다.
