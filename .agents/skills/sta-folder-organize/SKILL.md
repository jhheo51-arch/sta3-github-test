# sta-folder-organize

버전별 결과물을 삭제하지 않으면서, 다음에도 최신본을 쉽게 찾을 수 있는 구조로 정리한다.

## 고정 순서

진행할 때 현재 단계를 `[폴더 정리 1/7]`처럼 표시한다.

1. **안전 규칙 확인**: 정리할 프로젝트 폴더를 하나로 한정한다.
2. **읽기 전용 점검**: `scripts/inventory.ps1`로 전체 파일 수, 자동 생성 폴더 제외 수, 최신본 후보, 빈 폴더·중복 후보와 주의사항을 확인한다. 이미 정리된 후보면 README 근거와 기능만 확인하고 이동 없이 끝낼 수 있다.
3. **분류와 이동 계획 미리보기**: 항목을 `current`, `version`, `package`, `tool`, `qa`, `asset`, `review`로 분류한다. 판단이 어려운 항목은 삭제하지 않고 `review/` 보관 후보로만 둔다. 이동표 JSON을 새 파일로 작성하고 `scripts/create-plan.ps1`로 원래 위치·새 위치·분류 이유·크기·SHA-256·경로 참조 후보를 기록한다.
4. **사용자 확인**: 최신본이 모호하면 중단하고 질문한다. 이동이 있으면 `기존 경로 → 새 경로`, 분류 이유, 계획 파일 SHA-256 확인값을 함께 보여준다. 현재 요청이 그 정확한 계획의 실행을 명시적으로 승인했다면 같은 승인을 반복해서 묻지 않는다.
5. **정리와 경로 수정**: `scripts/apply-plan.ps1 -Approved`로 승인된 파일만 이동한다. 그다음 이동된 파일을 참조하는 코드와 문서 경로를 수정한다.
6. **검증**: 이동 전후 파일 수와 확인값을 비교하고, 경로 수정 여부·기능 검사·사용자 화면 확인을 서로 다른 상태로 기록한다. 실패하면 추가 이동을 멈추고 진행 기록의 원인을 설명한다. 같은 계획을 재개할 때만 `-Resume`을 사용한다.
7. **안내와 기록**: 프로젝트 `README.md`에 현재 실행 파일과 구조를 안내하고, 스타터 킷 최상위 `작업일지.md`에 결과와 사용자가 확인하지 않은 부분을 기록한다.

## 읽기 전용 점검 실행

PowerShell에서 이 스킬 폴더를 기준으로 다음 스크립트를 실행한다.

```powershell
& scripts/inventory.ps1 `
  -TargetPath "정리할 프로젝트의 절대 경로" `
  -AllowedRootPath "스타터 킷 또는 허용된 작업 상위 폴더의 절대 경로"
```

출력은 Codex가 안정적으로 읽을 수 있는 JSON이다. `suggestedLatest`는 이름과 현재 구조를 바탕으로 한 후보일 뿐, 실제 최신본을 확정하는 증거가 아니다. `already-organized-candidate`가 나오고 변경할 항목이 없다면 빈 이동 계획을 만들지 말고 검증과 기록만 수행한다. 빈 폴더와 중복 파일도 삭제 후보가 아니라 검토 후보다.

## 이동 계획 만들기

먼저 프로젝트 안에 겹치지 않는 이름의 이동표 JSON을 만든다. 경로는 프로젝트를 기준으로 한 상대 경로만 사용한다.

```json
{
  "items": [
    {
      "source": "index-v08.html",
      "destination": "current/index.html",
      "role": "current",
      "reason": "작업일지와 배포본 확인값이 일치하는 최신 실행 파일"
    },
    {
      "source": "용도불명-초안.html",
      "destination": "review/용도불명-초안.html",
      "role": "review",
      "reason": "최신본 또는 이전본인지 판단할 근거가 부족함",
      "reviewAfter": "2026-10-14"
    }
  ]
}
```

다음 명령으로 파일과 폴더의 확인값이 포함된 계획을 만든다. 출력 파일이 이미 있으면 새 버전 이름을 사용한다.

```powershell
& scripts/create-plan.ps1 `
  -TargetPath "프로젝트 절대 경로" `
  -AllowedRootPath "스타터 킷 절대 경로" `
  -MoveMapPath "이동표 JSON 절대 경로" `
  -OutputPath "프로젝트/folder-organize-plan-날짜-v01.json"
```

계획의 모든 `source`, `destination`, `role`, `reason`, `sizeBytes`, `sha256`, `pathReferences`를 사용자에게 요약한다. `review`에는 검토 예정일 `reviewAfter`가 반드시 필요하다. 최신본이 모호하면 실행 단계로 넘어가지 않는다. 계획 생성 결과의 `planFileSha256`도 함께 보여주며, 이후 계획 파일이 달라지면 새 승인을 받는다.

## 승인된 계획 실행

사용자가 계획 실행을 승인했을 때만 `-Approved`를 붙인다. 이 스위치가 없으면 스크립트는 아무것도 이동하지 않는다.

```powershell
& scripts/apply-plan.ps1 `
  -PlanPath "프로젝트/folder-organize-plan-날짜-v01.json" `
  -ApprovedPlanSha256 "사용자가 확인한 계획 파일 SHA-256" `
  -VerificationPath "프로젝트/folder-organize-verification-날짜-v01.json" `
  -ProgressPath "프로젝트/folder-organize-progress-날짜-v01.jsonl" `
  -Approved
```

스크립트는 승인한 계획 파일의 확인값과 현재 파일을 먼저 비교한 뒤 전체 항목을 점검한다. 원본 확인값이 달라졌거나 대상이 이미 있으면 하나도 이동하지 않고 중단한다. 이동 직후 내용이 같지 않으면 추가 이동을 멈추고 JSONL 진행 기록에 원인을 추가한다. JSONL은 한 줄마다 사건 하나를 덧붙이는 기록 형식이라 기존 기록을 덮어쓰지 않는다.

중간에 멈춘 같은 계획을 이어갈 때는 기존 진행 기록과 새 검증 파일명을 지정하고 `-Resume`을 추가한다. 이미 목적지에 있고 계획의 확인값과 일치하는 항목만 완료로 건너뛴다. 다른 계획이나 확인값이 다른 파일에는 재개를 사용하지 않는다.

## 이동 후 마무리

1. 계획의 `pathReferences`와 `rg` 검색 결과로 이전 경로를 확인한다. 발견된 코드·기획서·검사 파일만 `apply_patch`로 수정한다.
2. 최신 실행 파일과 배포 원본처럼 같아야 하는 파일은 SHA-256으로 비교한다.
3. 기존 자동 검사가 있으면 새 위치에서 실행한다.
4. 프로젝트 `README.md`와 최상위 `작업일지.md`를 갱신한다.
5. 실제 브라우저 조작은 사용자가 확인하기 전까지 완료로 기록하지 않는다.

## 안전 규칙

- 대상의 절대 경로를 확인하고 지정된 프로젝트 폴더 안인지 검증한다.
- `$HOME`, `~`, 드라이브 루트, 스타터 킷 전체를 이동·삭제 대상으로 사용하지 않는다.
- 파일과 폴더를 자동으로 삭제하지 않는다.
- 빈 폴더·중복 파일·용도 불명 항목도 자동 삭제하지 않는다. 필요성이 불명확하면 `review/` 이동만 제안하고 이유와 검토 예정일을 기록한다.
- 기존 결과물을 덮어쓰지 않는다. 대상 경로가 이미 있으면 중단한다.
- 이동 전 원래 경로, 새 경로, 파일 크기와 SHA-256 확인값을 기록한다.
- 버전 번호가 가장 높더라도 기획서·작업일지·실제 파일 내용이 충돌하면 최신본을 자동 확정하지 않는다.
- `node_modules`, `.git`, `dist`, `.next`, `.wrangler`, `.vercel`, `.cache`, `coverage` 등 자동 생성 폴더의 내부는 기본 정리 대상에서 제외한다.
- 이동은 명시적으로 나열된 경로만 수행한다. 넓은 와일드카드 이동과 재귀 삭제를 사용하지 않는다.
- 한 계획에서 부모 폴더와 그 안의 자식 항목을 동시에 이동하지 않는다.
- 파일을 이동한 뒤 코드·검사 프로그램·문서가 참조하는 상대 경로를 검색하고 수정한다.
- 실제 화면 조작을 확인하지 않았다면 자동 검사 통과와 구분해서 기록한다.

## 기본 결과 구조

파일 역할이 맞을 때만 아래 구조를 제안한다. 모든 프로젝트에 빈 폴더를 강제로 만들지 않는다.

```text
프로젝트/
├─ README.md
├─ current/          현재 사용할 최신본
├─ versions/
│  ├─ html/          이전 실행 파일
│  ├─ prd/           이전 기획서
│  └─ site/          이전 사이트 원본
├─ packages/         배포용 압축본
├─ tools/
│  ├─ update/        제작·수정 도구
│  ├─ verify/        검사 도구
│  ├─ stages/        배포 중간 자료
│  └─ vendor/        외부 도구와 사용 허가문
├─ qa/               화면 확인 자료
└─ assets/           결과물에서 사용하는 원본 자료
```

## 중단하고 확인할 때

- 같은 최고 버전 후보가 여러 개일 때
- 버전 번호와 수정 시각이 서로 다른 최신본을 가리킬 때
- 두 폴더가 같은 프로젝트인지 복사본인지 판단할 수 없을 때
- 이동하면 코드 경로가 깨질 수 있지만 수정 위치를 찾지 못했을 때
- 파일 수나 SHA-256 확인값이 이동 전후에 달라졌을 때
- 대상 경로가 프로젝트 밖으로 해석될 때
- 계획 생성 이후 원본의 크기나 SHA-256 확인값이 달라졌을 때
- 승인받은 계획 파일의 SHA-256 확인값이 실행 시점과 다를 때
- 중간 실패 후 다른 계획으로 재개하려 할 때
