# sta-make-prd : 한 장짜리 기획서 만들기

## 목적

`$sta-define-problem`에서 모은 정보(또는 참가자가 이미 말한 내용)로, 비개발자도 읽을 수 있는 한 장짜리 기획서(PRD)를 쓰고 어떤 방식으로 만들지 정한다.

PRD는 "무엇을 만들고 어떤 결과가 나오면 되는지" 적은 기획서라고 쉽게 설명한다. "이걸 만들자"는 약속이자, 이후 Codex가 작업할 때 보는 설계도다. 양식은 같은 폴더의 `template.md`.

## 진행 방법

1. 정보가 충분한지 확인한다
   - 부족하면 "조금만 더 여쭤볼게요" 하고 빈 칸만 1~2개 묻는다. 중요한 것부터
   - 아직 아무것도 안 정해졌으면 `$sta-define-problem`을 먼저 권한다
   - 참가자가 지정한 양식이 있으면 그것을 우선 쓴다. 현재 실습 README에 양식이 안내되어 있으면 그 파일을 쓴다
2. 크기를 점검한다. "남은 실습 시간에 무엇을 완성할 것인가?" (아래 "⏱️ 오늘 안에 끝나는 크기인가")
   - 로그인, 저장, 여러 화면, AI 기능을 어렵다는 이유만으로 빼지 않는다
   - 이미 쓴 시간과 외부 절차를 확인하고, 마지막 30분의 마무리 시간을 제외해 오늘 목표를 정한다. 종료 시각을 이미 알면 다시 묻지 않는다
   - `$sta-define-problem`에서 정리했더라도 PRD로 옮기며 핵심이 흐려지지 않았는지 한 번 더 본다
3. `template.md` 형식에 맞춰 채운다
   - "결과와 완료 조건"은 "어떤 입력이면 어떤 결과가 떠야 하는가"를 눈으로 확인할 수 있는 문장으로 쓴다
   - "핵심 기능"에서 AI에게 맡길 것과 사람이 확인할 것을 나눈다
   - 테스트 사례 3개(정상, 빈 값이나 누락, 사람이 확인할 예외)를 채운다
   - 참가자가 정하지 않은 것은 미정으로 표시한다. 점수 기준이나 기능을 임의로 확정하지 않는다
4. 만드는 방식을 정한다 (아래 "만드는 방식 판단표")
5. 참가자에게 쉬운 말로 요약해 보여주고 "이걸로 진행할까요?"라고 확인받는다
6. 확인되면 파일로 저장한다
   - 저장 위치 : 참가자가 지정한 곳. 지정이 없으면 현재 문제의 프로젝트 폴더 `projects/주제-날짜-v01/` (`$sta-define-problem`에서 만든 폴더). 프로젝트 폴더가 없으면 새로 만들고, 만들기 어려우면 현재 실습 폴더의 `output/`
   - 파일명 : `기획서-주제-YYYY-MM-DD-v01.md`처럼 주제, 날짜, 버전을 붙인다. 같은 이름이 있으면 덮어쓰지 않고 다음 버전으로 저장한다 (AGENTS.md 저장 규칙)
   - 저장 후 "첫 구현 목표(30분 예산)"부터 바로 시작한다
7. `작업일지.md`에 기획서 경로와 정한 내용을 적는다. 기록한다는 안내는 처음 한 번만 한다
   > "오늘 하는 건 제가 `작업일지.md`에 계속 적어둘게요. 나중에 '오늘 뭐 했더라?' 할 때 보시면 돼요."
   그 뒤로는 조용히 갱신만 한다. 매번 "적었어요"라고 하면 흐름이 끊긴다

⚠️ 참가자 확인 없이 곧바로 코드를 만들지 않는다. 반드시 "이걸로 진행할까요?" 단계를 거친다. 다만 이미 구현까지 요청받았다면 같은 승인을 반복해서 묻지 않는다.

## PRD에 담을 항목

(자세한 양식은 `template.md`)

1. 풀고자 하는 문제 : 지금은 어떻게 / 뭐가 불편 / 어떻게 되면 좋겠다
2. 사용자 : 누가, 언제, 어디서 쓰나
3. 입력 자료 : 사용할 파일이나 입력 내용, 필수 항목, 개인정보 포함 여부
4. 핵심 기능 (MVP) 3~5개 : 이것만 되면 일단 성공. AI에게 맡길 것 / 사람이 확인할 것
5. 결과와 완료 조건 : 결과물과 저장 위치, 어떤 입력이면 어떤 결과, 실패하면 무엇이 보이나
6. 나중에 추가할 것 : 지금은 안 만들지만 욕심나는 것. 적어두고 미룬다
7. 만드는 방식과 공유 방법 : 일회성 / 자동화 / 도구·웹 중 어디인가, 다 되면 어떻게 남에게 전달하나
8. 오늘 남은 시간에 완성을 목표로 할 것 : 핵심 목적과 마무리를 포함한 범위
9. 첫 구현 목표 (30분 예산) : 가장 먼저 눈으로 확인할 결과물
10. 테스트 사례 3개

## ⏱️ 오늘 안에 끝나는 크기인가

문제 정의와 기획서 작성에 이미 쓴 시간을 포함하고, 남은 시간을 기준으로 PRD의 목표를 정한다. 실습 종료 시각은 강사 안내로 확인한다.

30분은 첫 구현에 배정하는 예산이지 완료 약속이 아니다. 핵심 동작을 확인한 뒤 실제 소요 시간에 따라 계획을 갱신한다.

### 어렵다는 이유만으로 빼지 않을 구현 후보
- 핵심 기능 3~5개
- 화면(페이지) 여러 개 : 목록, 상세, 수정, 삭제
- 입력한 것이 계속 쌓이는 저장
- 간단한 로그인
- AI 기능 (요약, 분류, 생성, 챗봇)
- 시간이 남을 때 추가 개선

### 계획 조절이 필요한 신호
- ⏳ 심사나 승인 대기 (앱스토어 등록, 카톡 알림톡, 사업자 심사가 필요한 API)
- 💳 사업자 등록, 결제(PG) 연동
- 🙋 참가자가 줄줄이 밟아야 하는 가입, 승인 절차
- 📭 분석할 데이터, 연동할 시트가 아직 없음
- 오류 수정이나 연동이 지연되어 남은 시간에 핵심 동작과 마무리를 확인하기 어려움

신호가 보이면 "안 됩니다"가 아니라 3박자로 나눈다. 오늘 여기까지 됩니다 => 더 가려면 이런 대가 => 일단 이걸로 갈게요.
미룬 것은 PRD "나중에 추가할 것"에 적어둔다. 버리지 않고 미룬다.

## 만드는 방식 판단표

참가자의 답을 아래에 대입해서 정한다.

| 이런 상황이면 | 분기 | 만드는 방식 | 다 되면 어떻게 전달하나 |
|---|---|---|---|
| 딱 한 번, 또는 가끔 직접 돌리는 작업 (자료 정리, 분석 한 번) | 일회성 | Codex에서 직접 실행. 결과는 프로젝트 폴더나 `output/`에 파일로 | 배포 없음. 결과 파일 그대로 공유. 또 할 작업이면 스킬로 저장해 다음에 `$이름`으로 재사용 |
| 내가 안 보는 사이에도 자동으로 돌아야 함 (폼 응답 오면 자동 메일) | 자동화 | Google Apps Script | 구글에서 "웹앱으로 게시" 또는 시트, 폼 링크 공유 |
| 내가(또는 고객이) 계속 열어서 쓰는 도구, 웹 | 도구·웹 | 기본은 `index.html` 한 파일. 한 파일에 다 들어가고 더블클릭으로 열린다. 여러 화면, 저장, 로그인이 필요하면 Next.js | 파일이나 폴더로 전달. 인터넷 주소가 필요하면 PRD에 적어두고 방법은 강사와 확인 |

한 줄 판단 기준
> 내가 잠잘 때도 돌아야 하면 => Apps Script.
> 내가 깨어서 직접 쓸 때만 돌면 => Codex에서 직접 / HTML 도구.

📱 참가자가 "앱"을 원하면 웹앱으로 정한다. 비개발자는 "앱 = 폰에서 아이콘 눌러 여는 것"으로만 아는 경우가 많다. 웹앱은 설치 불필요, 안드로이드와 아이폰 한 번에, 심사 없음, 비용 없음, 홈 화면에 추가하면 앱처럼 보인다. 폰에서 잘 보이게(모바일 우선) 만든다. 진짜 스토어 앱은 개발자 등록 비용(애플 연 $99, 구글 1회 $25)과 심사가 든다고 솔직히 안내하고, 오늘은 웹앱을 추천한다.

## "이걸로 진행할까요?" 확인 예시

> **Codex**: 정리해봤어요. 이렇게 만들면 될 것 같아요.
>
> **만들 것**: 고객 문의 메일을 붙여넣으면 유형을 분류하고 답장 초안을 만들어주는 나만 쓰는 페이지
> **입력**: 문의 메일 본문 (이름, 연락처는 지우고 넣기)
> **AI가 할 것**: 유형 분류, 초안 작성 / **사람이 할 것**: 초안 확인 후 발송
> **오늘 목표**: 문의 3건을 넣으면 각각 유형과 초안이 화면에 뜨고, 결과가 `output/`에 파일로 남는 버전
> **첫 30분 목표**: 문의 하나를 붙여넣고 버튼을 누르면 유형과 초안이 화면에 뜨는 가장 단순한 버전
> **만드는 방식**: `index.html` 한 파일
> **나중에 추가할 것**: 메일 자동 발송
>
> 이걸로 진행할까요? 좋으시면 기획서를 `projects/문의답장-2026-09-08-v01/`에 저장하고 바로 만들기 시작할게요. 수정하고 싶은 부분 있으면 말씀해 주세요.

확인받으면 저장하고 첫 30분 목표부터 만든다.
