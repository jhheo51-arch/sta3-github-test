# sta-sos : 강사 호출용 상황 브리핑

## 목적

참가자가 막혀서 사람(강사)의 도움이 필요할 때, 지금까지의 상황을 강사가 15초 안에 읽을 수 있는 한 화면짜리 브리핑으로 압축한다.

강사는 노트북 앞에 서는 순간 항상 같은 처지다. 시간 2~3분, 맥락 0, 참가자는 설명을 못 한다. 지금 이 상황을 온전히 아는 것은 대화를 처음부터 겪은 Codex뿐이다. 그것을 꺼내주는 것이 이 스킬의 전부다.

재료는 세 가지다. 현재 대화, 실행 결과, 그리고 `output/`이나 `projects/` 폴더와 `작업일지.md`에서 확인한 내용. 여기서 확인한 것만 쓴다.

## ⚠️ 이 스킬만 워크샵의 다른 규칙을 깬다 (가장 중요)

읽는 사람이 참가자가 아니라 강사다. 평소 규칙을 정반대로 적용한다.

| 평소 (참가자용) | 이 스킬 (강사용) |
|---|---|
| 쉬운 말, 비유로 풀어서 | 전문 용어 그대로 ("환경변수", "인코딩", "권한 거부") |
| 존댓말로 친절하게 설명 | 압축된 개조식. 문장 짧게, 군더더기 0 |
| 안심시키는 톤 | 사실 위주. 위로 문구 금지 |
| 길어도 괜찮음 | 한 화면. 스크롤이 생기면 실패 |

강사에게 "환경변수는 보관함 같은 거예요"를 읽히지 않는다. 시간 낭비다.

단, 브리핑을 띄우기 직전 참가자에게 하는 안내 한 줄은 평소처럼 쉽고 따뜻하게.
> "강사님께 보여드릴 요약을 만들었어요. 손 들고 이 화면 보여주시면 돼요. 설명 안 하셔도 됩니다."

브리핑은 화면으로 보여준다. Slack이나 메일로 직접 보내지 않는다. 개인 대화 원문, 비밀번호, API 키는 브리핑에 넣지 않는다.

## 🚦 1단계 : 급한지 신호등 찍기 (제일 먼저)

강사는 여러 명을 돌고 있다. "여기 지금 봐야 하나?"에 대한 답을 우상단에 신호등으로 먼저 찍는다.

| 신호 | 언제 | 뜻 |
|---|---|---|
| 🔴 개입 필요 | 참가자 혼자서는 절대 못 넘김 (설치, 권한, 계정, 결정) | 지금 오세요 |
| 🟡 5분 뒤 다시 | 시도 중인 해결책이 있지만 확신이 없음 | 다른 데 먼저 보고 오세요 |
| 🟢 괜찮음 | 원인이 명확하고 Codex가 고치는 중 | 그냥 지나가세요 |

🟢을 정직하게 찍는 것이 이 스킬의 절반이다. "여긴 안 봐도 된다"는 신호가 강사에게 제일 값지다.
애매하면 🟡. 🔴을 남발하면 신호등이 무의미해진다.

## 🏷️ 2단계 : 막힌 유형 분류

강사의 다음 행동이 유형에 따라 완전히 달라진다. 하나만 고른다.

| 유형 | 이런 거 | 강사가 할 일 |
|---|---|---|
| ⚙️ 환경, 설치 | 명령어 없음, 설치 실패, 권한 거부, 경로 문제 | 강사가 직접 손댐 (관리자 암호 필요할 수 있음) |
| 🔑 계정, 절차 | 가입, API 키 발급, 로그인, 결제 등록 | 옆에서 같이 클릭 |
| 📐 크기 | 만들려는 게 오늘 안에 안 끝나는 크기 | 대화로 재정의 (=> 오늘 버전 / 나중 버전 분리, `$sta-improve`) |
| 🌫️ 정의 안 됨 | 뭘 만들지 자체가 아직 흐릿함 | 대화로 좁히기 (=> `$sta-define-problem`) |
| 🐛 코드 버그 | 코드가 원인, 원인도 대략 알고 있음 | 없음. Codex가 처리 중 (=> 🟢) |
| ❓ 원인 불명 | 세 번 시도했는데 원인 자체를 모름 | 같이 봐야 함 |

## 📄 3단계 : 브리핑 출력

아래 형식 그대로 출력한다. 칸을 비우지 말고, 모르면 "확인 안 됨"이라고 쓴다.

```
🆘 상황 브리핑                                🔴 개입 필요
────────────────────────────────────────────────────
만들려던 것   카톡 대화 분석 => HTML 리포트
진행 상황     4단계 중 3단계. 집계까지 됨, 리포트 파일 생성에서 멈춤
막힌 유형     ⚙️ 환경 문제 (코드 문제 아님)
경과          약 25분째 / 3회 시도
────────────────────────────────────────────────────
읽은 파일     day01/data/kakao.txt, day01/README.md
실행한 것     집계 스크립트 1회 (성공), 리포트 생성 3회 (실패)
만든 파일     day01/output/kakao-집계-2026-09-08-v01.csv
────────────────────────────────────────────────────
[사실]  리포트 생성 시 command not found. 3회 반복.
[사실]  macOS. 설치 시도 => Permission denied.
[추측]  실행 도구 미설치로 보임. 확인 필요.
[시도]  설치 명령 ✗ / 공식 설치 파일 안내 => 참가자가 못 찾음
[제안]  설치가 오래 걸리면 오늘은 HTML 한 파일로 우회 가능
────────────────────────────────────────────────────
마지막 에러 (원문)
  zsh: command not found: node
────────────────────────────────────────────────────
강사 액션     터미널에서 설치. 참가자 계정 암호 필요.
혼자 넘길 수 있나?  ❌ 불가
```

### 각 칸 작성 규칙

- 만들려던 것 : 기술 이름이 아니라 결과물로. ("Next.js 앱" ✗ => "리뷰 모아서 요약해주는 페이지" ✓)
- 진행 상황 : "어디까지 됐고 어디서 멈췄는지". 되는 것도 반드시 적는다. 강사가 처음부터 안 봐도 되게
- 경과 : 몇 분째, 몇 번 시도. 강사의 조급함 판단에 직접 쓰인다. 기록이 있을 때만 적고, 없으면 "확인 안 됨"
- 읽은 파일 / 실행한 것 / 만든 파일 : 대화와 `output/`에서 확인한 것만. 만든 파일은 경로 그대로
- `[사실]` : 실제로 관찰된 것만. 에러 메시지, OS, 실행한 명령. 추측을 섞지 않는다
  ⚠️ 에러 코드와 메시지는 대화 기억으로 쓰지 말고 마지막 에러 원문에서 다시 확인해서 쓴다. 기억 속 "401"이 원문에선 "400"인 경우가 실제로 있다. 어긋나면 강사가 헛짚는다
- `[추측]` : 원인 가설. 반드시 이 태그로 분리 (⚠️ 아래 주의)
- `[시도]` : 뭘 해봤고 어떻게 실패했는지. 강사가 같은 것을 또 시도하는 것을 막는다. 가장 실용적인 줄
- `[제안]` : 우회로가 보이면. 없으면 생략 (⚠️ 아래 주의)
- 마지막 에러 (원문) : 최대 5줄. 요약, 번역, 정리하지 않고 그대로. 없으면 이 칸 통째로 생략
- 강사 액션 : 강사가 손으로 할 일 한 줄. 필요한 것(암호, 카드, 계정)도 같이

### ⚠️ 주의 2가지

1. `[사실]`과 `[추측]`을 절대 섞지 않는다.
   Codex가 자신 있게 오진하면 강사가 엉뚱한 데를 판다. 혼자 볼 때보다 더 느려진다.
   확실하지 않으면 전부 `[추측]`으로. 그게 정직하고, 강사는 추측만 걸러 읽을 수 있다.

2. `[제안]`은 제안일 뿐이다.
   "이렇게 하세요"가 아니라 "이런 우회도 있음" 톤으로. 판단은 강사 몫이다. 강사가 한 줄로 무시할 수 있게 쓴다.

## 4단계 : 작업일지에 조용히 한 줄

브리핑을 띄운 뒤 `작업일지.md`의 "막혔던 것" 아래에 한 줄만 덧붙인다. 기존 내용은 덮어쓰지 않고 맨 아래에 추가한다.

```
- ⚙️ 환경 : node 미설치, 3회 시도 => 강사 도움 요청
```

- 참가자에게 이 기록 얘기를 꺼내지 않는다. 지금은 막혀서 예민한 순간이다. 조용히 남기고 넘어간다
- 나중에 "오늘 이런 걸 넘으셨네요" 회고에 쓴다
- ⚠️ 기록하느라 해결이 늦어지면 본말전도다. 한 줄이면 충분하다. 브리핑이 먼저다

## 그리고 바로 이어서 할 일

참가자를 놀려두지 않는다. 브리핑을 띄운 직후:

1. 강사를 기다리는 동안 할 수 있는 것을 찾아 계속 진행한다. 막힌 지점을 우회해서 만들 수 있는 다른 부분이 대개 있다
   > "강사님 오시는 동안 저는 리포트 디자인 부분부터 만들어둘게요. 그건 지금도 되거든요."
2. 할 게 정말 없으면 지금까지 만든 것을 보여주면서 기다리게 한다. 빈 화면 앞에 두지 않는다
3. "제가 못 해서 죄송해요" 톤 금지. "이건 사람이 직접 보는 게 빠른 종류예요"로
4. 요약 요청만으로 새 기능이나 우회 작업을 시작하지 않는다. 도움받을 시각을 약속하지 않는다

## 언제 이 스킬을 먼저 권할까 (Codex가 판단)

참가자가 부르지 않아도 아래 신호가 보이면 Codex가 먼저 권한다.

- 같은 에러로 세 번째 시도 중
- 환경, 설치, 권한 문제라 Codex가 직접 못 고침
- 참가자가 직접 해야 하는 절차(가입, 결제, 승인)에서 멈춤
- 비용이나 결정이 걸려서 참가자가 판단해야 함
- 참가자가 지쳐 보임 ("아 모르겠어요", "그냥 안 할래요")

> "이건 화면을 직접 보시는 게 빠를 것 같아요. 손 들어서 강사님께 여쭤보세요. 제가 상황 요약을 만들어드릴게요. 그거 보여드리면 설명 안 하셔도 돼요."

### ⚠️ 회피용으로 쓰지 않는다

코드로 풀 수 있는 것은 그냥 고친다. 이 스킬은 사람의 손, 결정, 승인, 계정이 필요할 때만이다. 어렵다는 이유로 강사에게 넘기면, 강사도 결국 Codex에게 시킬 뿐이다.
