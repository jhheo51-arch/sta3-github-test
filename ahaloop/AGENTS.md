# InsightFlow CRM 프로젝트 운영 지침

이 폴더는 기존 `InsightFlow CRM PRD v5.0`에서 출발해, 최신 `아하루프 혜택 회수 PRD v1.0`을 중심으로 초기 서비스 모델을 구현하고 계속 개선하는 전용 프로젝트입니다. 사용자 화면, 운영 화면, 데이터 구조와 검증 기록을 한곳에서 관리합니다.

## 소통 원칙

- 사용자에게는 한국어 존댓말로 설명합니다.
- 구현 결과와 사용자가 확인할 화면을 먼저 말하고, 기술 용어는 필요한 만큼만 풀이합니다.
- 제품 방향을 바꾸는 정보만 질문하고, PRD로 판단 가능한 내용은 합리적으로 진행합니다.
- 실행하지 않았거나 사용자가 확인하지 않은 결과를 완료로 기록하지 않습니다.

## 작업 시작 전 확인

1. `작업일지.md`의 마지막 기록을 읽어 현재 상태와 다음 할 일을 확인합니다.
2. 현재 제품 요구는 `docs/AHALOOP_Benefit_Recovery_PRD_v1.0.md`를 우선 기준으로 삼고, 기존 이력은 `docs/InsightFlow_CRM_PRD_v5.0.docx`를 참고합니다.
3. InsightFlow의 기능·화면·데이터·운영 흐름을 바꾸는 작업에는 프로젝트 스킬 `.agents/skills/insightflow-crm/SKILL.md`를 사용합니다.
4. 기존 변경사항을 확인하고 사용자의 작업을 임의로 되돌리지 않습니다.

## 제품 기준

- 이 프로젝트는 사용자의 BA, CRM·데이터 활용, Consultant, PM 역량을 증명하는 취업 포트폴리오이기도 합니다. 기능만 추가하지 말고 문제 정의, 요구 구조화, 데이터·이벤트, KPI, 가설, 우선순위와 검증 근거가 연결되게 관리합니다.
- 데모 수치와 실제 사용 데이터를 명확히 구분하고, 미구현·미검증 항목을 포트폴리오 성과처럼 표현하지 않습니다. 직무별 근거는 `docs/AHALOOP_Career_Portfolio_Evidence_v1.0.md`에서 관리합니다.

- 최신 제품의 핵심은 뉴스·인사이트 추천이 아니라 `혜택 발견 → 조건 확인 → 서류 준비 → 신청 → 승인 → 수령`을 잇는 혜택 회수입니다. `docs/AHALOOP_Benefit_Recovery_PRD_v1.0.md`가 아래 레거시 뉴스 규칙보다 우선합니다.
- 제품 약속은 `혜택을 찾는 서비스가 아니라, 혜택을 받기까지 사용자가 해야 할 일을 줄여주는 서비스`입니다. 신규 사용자는 지역·만 나이·생활 상태 세 번의 선택 안에 첫 혜택을 보고, 이후 한 화면에서 질문 또는 결정 하나만 받습니다.
- 아하루프 패스, 조건 재사용, 접근 부담 이벤트와 KPI를 바꿀 때 `.agents/skills/ahaloop-pass-harness/SKILL.md`를 사용하고 `npm run harness:pass`로 반복 검증합니다.
- `ahaloop/**` 코드와 프로젝트 자동화가 바뀌면 GitHub의 `AHALOOP harness` 검사를 통과해야 합니다. `main` 필수 검사를 우회하거나 실패를 성공으로 바꾸지 않습니다.
- 목록 개수보다 받을 가능성이 높은 가치를 먼저 보여 주되, 월간·1회성·비현금 가치를 구분하고 가정과 계산 근거를 표시합니다.
- 판정은 `가능성 높음`, `정보 필요`, `현재 대상 아님`, `다음 회차 감시`로 구분하고 공식 원문·확인일·부족한 조건을 함께 제공합니다.
- 실제 혜택 수집·판정·회수 자동화에는 `.agents/skills/ahaloop-benefit-recovery/SKILL.md`를 사용합니다.
- 고객 조건은 자격 판정에 필요한 최소 범위로 저장하고, 외부 제출이나 민감정보 제공은 별도 동의를 받습니다.
- 고객군은 전국의 전 생애주기와 가구상황으로 확장합니다. 학생·청년·직장인·구직자·가사 및 돌봄 전담자·중장년·노년·독거·한부모·조손·장애·돌봄 필요 가구를 직업 하나가 아니라 `연령·지역·가구·생활단계·필요`의 조합으로 판정합니다.
- 2026-09-26 첫 외부 검증 고객군은 `서울 거주 만 19~34세 직장인·구직자 중 최근 6개월 안에 정책·지원금 탐색 경험이 있는 5명`으로 좁힙니다. 제품의 전국·전 생애주기 범위는 유지하되, 파일럿에서는 마감이 있는 현금성 혜택의 발견부터 준비 시작까지를 우선 관찰하고 실제 증거 없이 다른 고객군 성과로 일반화하지 않습니다. `docs/AHALOOP_Pilot_Operations_v1.0.md`에 따라 `P01~P05` 익명 코드만 사용하고 빈 슬롯·계획을 성과로 집계하지 않습니다.
- 조건 수집은 2026-09-18 사용자 결정에 따라 선택형을 기본으로 합니다. 지역·만 나이는 선택 목록, 생활·가구·주거는 단일 선택, 필요한 도움은 복수 선택으로 제시합니다. 선택 요약·개별 해제·초기화를 제공하고 명시적 저장 후 판정에 반영합니다. 자연어 해석 API는 기존 실험용으로 보존하며 기본 고객 입력으로 요구하지 않습니다.
- 2026-09-22 아하루프 패스 결정: 첫 혜택 전에는 지역·만 나이·생활 상태만 차례로 묻고 세 번째 선택으로 첫 후보를 엽니다. 소득·가구·주거·알림은 첫 혜택 전에 강제하지 않고, 선택한 혜택에 필요한 조건을 한 번에 하나씩 확인합니다.
- 미선택·선택 해제·빈 숫자는 confirmedFields에서 제외합니다. 실제 0/false와 미확인을 구분하고 조건 초기화로 이름·알림 동의를 임의 변경하지 않습니다. 정확한 금액은 필요한 경우에만 선택 입력으로 받습니다.
- 자연어 해석에서 모르는 값은 기존 프로필 값으로 조용히 채우지 않습니다. 거주지와 나이, 현재 생활단계, 가구형태, 당장 필요한 도움 순으로 영향이 큰 질문을 한 번에 하나씩 묻습니다.
- 2026-09-18 최신 결정: 인증키 발급·로그인은 보류하고 공식 공개 공고 수집을 우선합니다. 청년몽땅정보통은 우선 연결 후보이며 아직 연결 완료로 표현하지 않습니다. 전국·전 생애주기 대상은 유지하되 실제 확인한 출처·지역 범위만 공개합니다. 보조금24·복지로 등 API는 향후 보완 후보로 보존합니다.
- 공개 공고의 이용 조건·자동 접근 허용 여부를 출처별로 확인합니다. 미확인·차단 상태에서는 예약 수집을 시작하거나 우회하지 않고 수동 확인·원문 연결을 사용합니다. 상세 운영 기준은 혜택 회수 스킬의 `references/public-notice-operations.md`를 따릅니다.
- 자동 수집, 변경 감시 설계, 수동 검수, 인증키 필요 상태를 분리합니다. 인증키가 없거나 실제 예약 실행이 없는 출처를 `자동 수집 중`으로 표시하지 않습니다.
- 공식 공개 공고는 현재 운영자 수동 실행으로 본문 해시를 비교합니다. 출처별 자동 접근 허용과 예약 실행이 확인되기 전에는 예약 자동화로 승격하지 않습니다.
- 신속성도 제품 품질입니다. 새 공고 발견 60분, 조건·기한 검수 180분, 검수 후 대상자 알림 30분을 초기 SLA로 추적하고, 마감 7일 이내·조건/금액 변경·안전 관련 혜택은 P0로 올립니다.
- 혜택 알림은 `새 혜택 발견·마감 임박·진행 이어가기·수령 확인`으로 구분하고, 받은 이유·가치 유형·마감·공식 확인일·다음 행동 하나를 포함합니다. 같은 사유의 중복 발송과 완료 단계 재촉은 억제합니다.
- 경쟁 서비스의 공개 패턴은 학습하되 비공개 로직을 사실처럼 추정하거나 문구·화면을 복제하지 않습니다. 아하루프의 차이는 전 생애주기 대상, 판정 근거, 수령 완료까지의 상태 연결로 증명합니다.

- 외부 브랜드의 공식 한글명은 `아하루프`, 영문명은 `AHALOOP`이다. 브랜드 표기와 시각 정체성은 `docs/AHALOOP_Brand_PRD_v1.0.md`를 따르고, 처음 보는 접점에는 `놓친 혜택을 받을 때까지` 또는 `혜택알림` 설명을 함께 사용합니다.
- `InsightFlow CRM`은 기존 PRD·폴더·코드·데이터에 남아 있는 레거시 내부 코드명으로만 유지하며, 새 사용자 노출 문구에는 사용하지 않는다.
- 기존 뉴스 MVP의 `관심 설정 → 이번 주 브리프 → Action Pulse` 흐름은 레거시 실험으로 보존하고 신규 고객 화면의 기본 여정으로 확장하지 않습니다.
- 사용자의 관심 분야와 관심 역할은 각각 최대 2개이며, 선택하지 않은 정보 유형은 발송 후보에서 제외합니다.
- 카드는 사실 중심 제목, 짧은 요약, 개인화 이유, 출처와 시점, 행동을 함께 제공합니다.
- 출처·마감일·문구는 운영자가 검수한 상태만 발송 가능한 것으로 처리합니다.
- 채널별 수신 동의와 철회 이력을 보존하고, 재개 안내는 동의한 사용자에게 7일 뒤 한 번만 제공합니다.
- 투자나 지원 결과를 단정하지 않고, 실제 서비스처럼 보이게 하기 위한 예시는 명확한 데모 데이터로 유지합니다.
- 흰 족제비 마스코트의 작업용 애칭은 `아루`이며, `public/brand/ahaloop-mascot-profile.png`를 고객 접점의 대표 프로필로 사용합니다. 애칭은 제품명보다 앞세우지 않습니다.
- `Action Pulse` 기능명은 유지하되 사용자 행동 문구는 `아하`의 발견이 `Loop`의 행동과 다음 추천으로 이어지는 말투를 사용하고, 행동의 실제 의미가 분명해야 합니다.
- `브리프`는 `한 주의 정보 흐름에서 나에게 필요한 맥락과 다음 행동만 이어 붙인 개인화 묶음`으로 정의하고 고객 화면에서도 이 명칭을 유지합니다.
- `오호, 더 보고 싶어요`는 관련 뉴스 1개를 즉시 추가하고 그 다음에 명확히 `광고`로 표시한 유료 영역을 노출합니다. 광고에는 `더 많은 흐름으로 이어가고 싶나요?` CTA를 두고 클릭을 `paid_loop_interest` 이벤트로 기록합니다. 광고는 편집 추천 순위나 평가 보상에 섞지 않습니다.
- 담당자 판단이 필요한 기능은 `담당자에게 검토 요청`처럼 결과가 분명한 문구를 쓰고, 고객이 문제를 10~1000자로 서술하게 하며, 요청 내용이 포함된 48시간 후속 작업으로 처리합니다.
- 인사이트 평가를 완료하면 다음 주 발송에 관련 뉴스 1개를 추가합니다. 이 보상 뒤에는 광고를 자동 노출하지 않습니다.
- 채널 발송 기능을 바꿀 때 운영자 작성 화면뿐 아니라 카카오톡·문자 수신 미리보기와 고객의 상세 인사이트 연결까지 함께 확인합니다.
- 실제 카카오톡 친구추가 URL은 채널 관리자센터에서 발급된 값만 사용하며, 발급 전에는 링크 자리를 명확한 플레이스홀더로 표시합니다.
- `.agents/skills/ahaloop-content-collector/SKILL.md`는 뉴스 기반 레거시 실험 유지보수에만 사용합니다.

## 구현과 검증

- 서브에이전트는 필요한 경우 기존 역할을 재사용합니다: `ba_review`는 조건·마감·예외, `crm_review`는 계정 분리·이벤트·동의·단계, `strategy_research`는 공식 출처·이용 조건·범위와 비용을 읽기 전용 검토합니다. 메인이 코드·스킬·배포를 통합합니다. 사용자 요청이나 적용 지침에 위임 근거가 있을 때만 구체적인 독립 과제를 맡기며 상시 실행으로 표현하지 않습니다.
- 재위임 시 최신 결정, 대상 파일, 읽기/쓰기 범위, 완료 기준을 전달합니다. 과거 검토 결과는 현재 결함으로 단정하지 말고 최신 코드와 공식 근거로 재현합니다. 특히 확인되지 않은 마감 시각을 과거 테스트에서 그대로 가져오지 않습니다.

- 2026-09-18 이후 포트폴리오 기준·요구 추적·측정 정의는 `docs/AHALOOP_Portfolio_Upgrade_v2.0.md`를 우선한다. 구현, 합성 검증, 실제 고객 관찰, 기관 확인을 구분한다.
- 고객 정보·신청·이벤트·근거는 Sites 서버 인증 ID로 격리한다. 요청 본문의 userId나 공통 demo-user로 고객을 선택하지 않는다. 운영 검증실은 현재 계정별 파일럿이며 조직 전체 관리자 화면으로 표현하지 않는다.
- 고객 화면과 운영 화면은 서버 역할로도 분리합니다. `AHALOOP_OPERATOR_USER_IDS`에 등록한 로그인 ID만 검증실·파일럿·실발송 테스트 API를 사용할 수 있으며 탭 숨김만 권한 통제로 보지 않습니다.
- 데이터 보관·삭제는 `docs/AHALOOP_Data_Retention_v1.0.md`를 따릅니다. 발송 시도 90일, 활동·평가·발송·원문 검수 180일, 후속 작업 365일을 접속 시 정리하며 프로필·신청함·동의·포트폴리오·파일럿 기록은 사용자의 전체 삭제 전까지 보관합니다.

- `preview_*`는 실제 발송·도달·클릭과 분리한다. 제공업체·동의·중복·피로도 검증 전 실발송을 열지 않는다. 출처 수동 실행을 예약 자동수집으로 표시하지 않는다.
