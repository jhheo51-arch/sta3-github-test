# 아하루프 발송 연결 파일럿

2026-09-18. 상태: 연결 코드 구현, 업체 계정·인증값 미설정, 실제 발송 미검증.

## 사용자 준비

1. [솔라피 시작하기](https://solapi.com/start)에서 직접 가입·본인 확인·발신번호 등록을 진행한다. 가입·충전·키 생성은 사용자 승인 없이 대신 실행하지 않는다.
2. 카카오톡은 아하루프 채널을 만들고 솔라피에 연결한 뒤 테스트 메시지 템플릿을 심사받는다. 심사 승인이나 비용은 보장하지 않는다.
3. 인증값과 본인 테스트 수신번호는 채팅·Git·작업일지에 넣지 않고 Sites 서버 비밀 설정으로 전달한다. 수신번호를 제공업체에 전달하는 목적과 이용 비용을 확인한 후 활성화한다.

## 서버 설정과 범위

- SOLAPI_API_KEY / SOLAPI_API_SECRET: 서버 인증. SMS는 SOLAPI_SENDER에 사전 등록된 발신번호를 설정한다.
- NOTIFICATION_PILOT_USER_ID: 서버 인증에서 확인한 운영자 테스트 사용자 ID. 클라이언트가 지정할 수 없다.
- NOTIFICATION_PILOT_PHONE: 운영자가 확인한 본인 수신번호, 숫자만 있는 010 번호. 아직 일반 고객의 번호 인증이나 연락처 등록 기능은 아니다.
- NOTIFICATION_SEND_ENABLED: 기본 false. 계정·잔액·등록번호·수신 동의를 확인한 후에만 true로 설정한다.
- 카카오톡은 SOLAPI_KAKAO_PFID / SOLAPI_KAKAO_TEMPLATE_ID 추가. 아래 고정 문구와 일치하는 변수 없는 승인 템플릿만 연결한다. 문자 대체발송은 꺼둔다.

고정 테스트 문구: `[아하루프] 요청하신 알림 연결 테스트입니다. 혜택 지급 확정 안내가 아닙니다.`

내 조건 → 알림 설정에서 준비 상태를 확인하고 마스킹된 수신처·문구·요금을 확인한 후 테스트 버튼을 직접 누른다. 이 테스트는 희망 채널 동의와 별도인 1회 명시적 요청이다. 자동 캠페인은 여전히 차단한다.

## 안전성과 검증

- 테스트 사용자만 발송 가능. 브라우저에서 임의 수신자·본문을 받지 않는다. 한국 날짜 기준 사용자당 하루 1회 원자적 예약으로 동시 요청 중복을 차단한다. 실패도 횟수에 포함한다.
- 서버에는 요청 ID·채널·상태·업체 메시지 ID·시각만 기록하고 수신번호·인증값·업체 원본 응답을 로그에 남기지 않는다.
- sending / accepted / failed / unknown을 분리한다. accepted는 접수이지 delivered가 아니다. 시간초과·불명확한 응답은 자동 재시도하지 않는다. 업체 콘솔 내역으로 확인한다.
- 이번 구현은 본인 번호로 연결을 검증하는 단계다. 고객별 전화번호 인증, 암호화 연락처·삭제 흐름, 채널별 동의 재확인, 혜택별 승인 템플릿, 도착 결과 동기화, 예약 발송·전체 비용 상한은 일반 고객 운영 전 추가 구현·검증이 필요하다.
- tests/notification-check.mjs는 외부 통신 없는 모의 응답 검사이며 실제 발송 증거가 아니다. 실제 확인은 계정 준비 후 본인에게 1건 보내 확인한다.

공식 구현 근거: [인증](https://solapi.com/developers/api/authentication-api-key), [메시지 발송](https://solapi.com/developers/api/messages), [알림톡](https://solapi.com/developers/api/messages-ata). 공급자 선택은 초기 연결 구현 기준이며 가입·유료 계약을 대신 체결한 것이 아니다.
