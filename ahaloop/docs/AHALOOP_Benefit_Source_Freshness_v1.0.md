# 아하루프 혜택 수집·신속성 설계 v1.0

작성일: 2026-09-14  
상태: 연결 준비와 현재 실제 운영 상태 구분

## 목적

혜택 개수를 늘리는 것과 늦지 않게 전달하는 것을 하나의 운영 문제로 다룬다. 수집량만 집계하지 않고 `공고 게시 → 발견 → 정규화 → 변경 감지 → 검수 → 대상자 재판정 → 알림`의 시간을 측정한다.

## 현재 실제 상태

- 사이트의 대표 혜택 11건은 2026-09-14 공식 원문을 직접 확인한 데모 데이터다.
- 자동 예약 수집은 아직 0개 출처다.
- 보조금24, 온통청년, 지자체 Open API는 공식 제공 여부를 확인했지만 인증키 발급과 운영 약관 확인이 필요하다.
- 복지로·고용24·전문기관 공식 페이지는 변경 감시 대상으로 설계했으며, 실제 예약 작업과 마지막 성공 로그가 생기기 전에는 `자동 수집 중`으로 표시하지 않는다.

## 신속성 SLA

- 공고 게시 후 발견: P0/P1 60분 이내
- 발견 후 조건·금액·기한 검수: 180분 이내
- 검수 후 동의한 대상자 알림: 30분 이내
- 마감 7일 이내, 조건·금액 변경, 안전·돌봄 위험: P0 승격
- 실패 2회: 운영 경고, 3회 연속: 해당 출처의 최신성 상태를 `지연`으로 노출하고 대체 원문 확인

## 데이터와 이벤트

- source: 제공기관, 방식, 연결상태, 확인주기, SLA, 마지막 시도·성공·오류
- benefit version: 공고 ID, 공식 URL, 원문 해시, 대상·금액·기한·서류 버전
- timing event: `source_checked`, `benefit_discovered`, `benefit_changed`, `review_completed`, `audience_recalculated`, `benefit_notified`
- KPI: 수집 성공률, 중복률, 변경 탐지 정밀도, 발견/검수/알림 지연 p50·p95, 마감 후 오발송률

## 연결 순서

1. 보조금24 API 키를 발급해 전국 기본 카탈로그와 상세 조건을 적재한다.
2. 온통청년 API 키를 발급해 청년정책 갱신 지연을 보완한다.
3. 복지로·고용24·전문기관의 허용된 원문 감시 방식과 이용약관을 확정한다.
4. 지역별 열린데이터를 17개 시도 단위로 등록하고 시군구 공고는 미수집 지역을 우선한다.
5. 실제 예약 실행·로그·검수 큐가 생긴 뒤에만 화면 상태를 `자동 수집 중`으로 바꾼다.
