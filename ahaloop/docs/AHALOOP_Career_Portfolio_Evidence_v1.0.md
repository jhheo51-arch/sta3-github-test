## 2026-09-26 목표 직무 결정

- 주 지원 직무: **BA**
- 차별화 방식: **컨설턴트식 문제 정의·대안 비교·권고**

아하루프의 현재 증거는 요구사항·예외·수용 기준, 현재/개선 프로세스, 데이터 구조와 운영 통제에 가장 강하다. 따라서 네 직무를 같은 비중으로 주장하지 않고, BA 사례를 중심으로 컨설턴트식 사고를 보여 준다. PM 역량은 5명 파일럿과 우선순위 변경 결과가 생기기 전까지 보조 역량으로만 표현한다.

## 결론

아하루프는 네 직무에 공통으로 필요한 `모호한 고객 문제 → 구조화된 조건 → 의사결정 규칙 → 행동 데이터 → 개선 실험`을 하나의 서비스로 보여 줄 수 있는 프로젝트다. 다만 UI 구현 자체가 아니라 아래 근거와 실제 검증 결과를 면접에서 설명할 수 있어야 한다.

## 핵심 사례 서술

### 문제

기존 정책 서비스는 혜택을 검색하거나 알리는 데 집중한다. 사용자는 자신이 대상인지, 얼마를 받을 수 있는지, 어떤 순서로 준비해야 하는지 판단하기 어렵다.

### 가설

서울 거주 만 19~34세 직장인·구직자에게 혜택 개수 대신 예상 가치와 다음 질문 하나를 먼저 보여 주면 조건 완료율과 준비 시작률이 높아진다.

### 제품 결정

- 초기 고객군을 서울 청년 직장인·구직자로 제한했다.
- 자유로운 자기 설명에서 조건과 근거를 추출하고, 부족한 정보는 한 번에 하나씩 묻는다.
- 월간·1회성·비현금 가치를 분리해 과장된 합계를 막는다.
- `발견 → 조건 확인 → 서류 → 신청 → 승인 → 수령` 상태를 CRM 이벤트와 연결한다.
- North Star를 콘텐츠 클릭이나 신청 수가 아닌 `고객 수령 완료 금액`으로 정했다.

## 데이터 설계

- Profile: 거주지, 출생연도, 고용·주거, 소득, 교통비, 생활 변화, 수신 동의
- Interpretation: 사용자의 원문, 추출한 조건, 근거, 신뢰도, 부족한 값
- Benefit: 공식 원문, 대상 규칙, 금액 유형·산식, 마감, 검수일
- Application: 조건 확인, 서류, 제출, 승인, 수령 단계와 예상 가치
- Event: 조건 저장, 근거 확인, 준비 시작, 감시, 단계 이동

## KPI와 분석 질문

- North Star: 고객 수령 완료 금액
- 퍼널: 타깃 확인 → 브리프 확인 → 준비 시작 → 신청 → 승인 → 수령
- 선행지표: 조건 확인 완료율, 브리프 대비 준비 시작률, 마감 전 신청률
- 안전지표: 판정 정정률, 공식 원문 불일치율, 알림 수신 거부율
- 세그먼트: 직장인/구직자, 연령대, 자치구, 주거 형태, 생활 변화

## 우선 실험

1. 자연어 조건 대화와 전체 입력폼의 조건 완료율 비교
2. 혜택 개수와 예상 가치 우선 제시의 준비 시작률 비교
3. 한 번에 한 질문과 여러 질문 묶음의 이탈률 비교

## 현재 부족한 부분

- 자연어 해석은 규칙 기반 데모이며 실제 언어모델·평가 데이터셋이 연결되지 않았다.
- 혜택 자격 규칙이 코드에 있고 운영자가 버전·변경 이력을 관리하는 규칙 엔진은 없다.
- 실제 사용자 코호트가 없어 현재 퍼널은 한 명의 데모 데이터만 보여 준다.
- 외부 신청 제출, 본인 인증, 서류 검증과 실제 수령 확인이 연결되지 않았다.
- 사용자 인터뷰, 경쟁 서비스 비교, 운영비와 수익 모델 검증이 아직 부족하다.

## 포트폴리오로 완성하기 위한 종료 조건

- 목표 사용자 10명 이상 인터뷰와 테스트
- 자연어 조건 50문장 이상의 정답셋과 필드별 정확도 측정
- 실제 사용 퍼널 2주 이상 수집 및 한 번의 실험 결과
- 오판정·마감 변경·중복 수혜 등 예외 10개 이상의 수용 기준
- 데이터 흐름도, 이벤트 명세, 의사결정 로그와 회고 완성
