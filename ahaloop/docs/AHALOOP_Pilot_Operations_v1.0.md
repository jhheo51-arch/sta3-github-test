# 아하루프 첫 파일럿 운영안 v1.0

## 목적

혜택을 많이 보여 주는지가 아니라, 사용자가 `세 번의 선택 안에 첫 혜택`에 도달하고 이후 `한 화면에서 한 가지 결정`만 하며 실제 준비를 시작할 수 있는지 확인합니다.

## 참가자와 범위

- 서울 거주 만 19~34세 직장인·구직자
- 최근 6개월 안에 정책·지원금 탐색 경험이 있는 사람
- 첫 라운드 5명, 익명 코드 `P01~P05`
- 마감이 있거나 준비 행동이 분명한 현금성 혜택을 우선 관찰
- 결과는 전국·전 생애주기 성과로 일반화하지 않음

## 40분 관찰 순서

1. 5분: 참여 동의, 녹화·개인정보 범위 안내
2. 10분: 최근 혜택 탐색 경험과 포기 지점 회상
3. 20분: 지역 → 만 나이 → 생활 상태 선택, 첫 혜택 확인, 다음 조건 1개 응답, 준비 시작
4. 5분: 신뢰한 근거, 부담스러운 요구, 다시 사용할 이유 확인

## 기록 원칙

- 검증실의 파일럿 화면에는 익명 코드, 동의 상태, 선택 수, 첫 혜택까지 시간, 첫 혜택 ID, 준비 시작 여부, 중단 지점과 관찰 메모만 저장합니다.
- 실명, 연락처, 주민등록번호, 계좌, 계약서·소득서류 원문은 저장하지 않습니다.
- 참가자가 완료하지 않은 단계를 완료로 표시하지 않습니다.
- 관찰자의 해석과 참가자의 실제 말·행동을 구분해 메모합니다.

## 성공·중단 기준

- 구현 목표: 3회 선택 안에 첫 혜택 노출, 그 뒤 한 화면 한 결정
- 탐색 지표: 첫 혜택 도달 인원, 3회 안 도달 인원, 준비 시작 인원, 중단 지점, 소요 시간
- 첫 5명은 문제 탐색 표본이므로 전환율 승자나 통계적 성과를 선언하지 않습니다.
- 3명 이상이 같은 핵심 과제에서 실패하거나, 잘못된 자격 확정·민감정보 노출이 발견되면 모집을 멈추고 수정합니다.

## 외부 의존 단계

- 참가자 모집·일정 확정·참여 동의는 운영자가 직접 진행해야 합니다.
- 외부 참여자에게 사이트를 열 때 고객 화면만 제공하고, `AHALOOP_OPERATOR_USER_IDS`에 포함된 계정만 검증실과 실제 발송 테스트에 접근합니다.
- 실제 문자·알림톡은 발송업체 계정, 발신번호, 카카오 채널·템플릿 승인과 별도 유료 발송 동의가 있어야 합니다.
- 공식 공고는 출처별 자동 접근 허용을 확인하기 전까지 검증실의 수동 원문 확인으로 운영합니다.

## 포트폴리오 증거

- BA: 요구사항, 예외, 판정 근거, 신청 상태 전이
- CRM: 고객 상태별 다음 행동, 동의·중복·조용한 시간, 발송 접수와 도착 구분
- Consultant: 공식 출처 운영비용과 실패 대응, 수동→자동 승격 조건
- PM: 문제 가설, 5명 관찰, 지표·중단 기준, 다음 우선순위 결정
