# 아하루프 브랜드 PRD v1.1

- 문서 상태: 혜택 회수 전환을 반영한 외부 브랜드 기준
- 제정일: 2026-09-11
- 적용 범위: 카카오톡 채널, 사용자 화면, 소개 자료, 마스코트와 향후 대외 커뮤니케이션
- 기반 제품 문서: `InsightFlow_CRM_PRD_v5.0.docx`

## 1. 문서 역할

이 문서는 서비스의 외부 브랜드명과 시각 정체성을 아하루프로 관리하는 공식 부록이다. 제품 정의는 `AHALOOP_Benefit_Recovery_PRD_v1.0.md`를 우선한다.

브랜드 관련 내용이 기존 PRD의 `InsightFlow` 표기와 충돌할 때는 이 문서가 우선한다. 관심 설정, 주간 카드 3~5개, Action Pulse, 평가, 후속 작업, 채널 동의와 KPI에 관한 제품 규칙은 기존 PRD v5.0을 계속 따른다.

## 2. 브랜드 정의

### 공식 명칭

- 한글: `아하루프`
- 영문: `AHALOOP`
- 발음: `아-하-루프`
- 현재 의미: `Aha`는 몰랐던 혜택과 자격을 발견하는 순간, `Loop`는 발견에서 끝내지 않고 조건 확인·준비·신청·수령까지 이어지고 생활 변화 때 다시 확인하는 반복

### 브랜드 한 문장

아하루프는 내 조건에 맞는 혜택을 먼저 찾아, 받을 때까지 다음 행동을 이어 주는 혜택 회수 서비스다.

### 권장 설명 문구

`놓친 혜택을 받을 때까지`

설명 문구는 상표명에 포함하지 않는다. 이름만으로 혜택 서비스임을 바로 알기 어려우므로 첫 화면, 채널명, 검색 결과와 소개 자료에서는 설명 문구 또는 `아하루프 혜택알림`을 함께 쓴다. 기존 `한 주의 인사이트를 행동으로`는 뉴스 기반 레거시 실험 문구로만 보존한다.

## 3. 해결하려는 문제와 브랜드 약속

### 문제

- 현금·할인·돌봄·교육 혜택이 기관과 지역별로 흩어져 있다.
- 사용자는 목록을 찾아도 내 자격, 준비 서류, 마감과 신청 후 상태를 따로 관리해야 한다.
- 기존 알림은 발견이나 홍보에서 끝나 실제 수령·이용 여부를 확인하기 어렵다.

### 약속

- 맞는 조건과 아직 모르는 조건을 근거와 함께 설명한다.
- 한 번에 질문 또는 다음 행동 하나만 제시한다.
- 발견에서 끝나지 않고 준비·신청·승인·수령까지 이어 준다.

## 4. 핵심 제품 흐름

아하루프의 핵심 흐름은 다음과 같다.

1. 평소 말투로 현재 생활 조건 설명
2. 맞는 조건과 부족한 조건 확인
3. 예상 가치·근거·마감·질문 하나로 구성된 혜택 브리프 수신
4. 서류 준비·신청·승인 상태 이어가기
5. 실제 수령·이용 확인 또는 다음 회차 감시

`Action Pulse`는 뉴스 기반 레거시 기능명으로 보존한다. 혜택 회수 여정의 고객 버튼은 `조건 확인하기`, `준비 이어가기`, `수령 확인하기`처럼 결과가 드러나는 표현을 쓴다.

## 5. 이름 적합성 판단

`아하루프`는 친근하고 기억하기 쉬우며 세금·청년 정책 한 분야에 갇히지 않아 전 생애주기 확장에 적합하다. 마스코트 `아루` 및 발견→행동→수령의 반복 구조와도 잘 맞는다.

다만 이름만으로 혜택 서비스라는 범주와 공공정보 신뢰성이 즉시 전달되지는 않는다. 따라서 마스터 브랜드는 유지하되 다음 보완을 필수로 한다.

- 사용자 접점 기본 표기: `아하루프 | 놓친 혜택을 받을 때까지`
- 알림 발신자·채널 권장 표기: `아하루프 혜택알림`
- 고령층 대상 문구에서는 `루프`, `브리프`만 단독으로 쓰지 말고 `받을 혜택`, `신청 준비`를 함께 설명
- 출시 전 무보조 이름 회상률, 서비스 범주 이해율, 신뢰도와 유사 상표를 검증

## 6. 이름 사용 규칙

### 외부 사용

다음과 같이 사용자나 고객에게 보이는 영역에는 `아하루프` 또는 `AHALOOP`를 사용한다.

- 카카오톡 채널명과 프로필
- 서비스 화면의 헤더와 메타데이터
- 사용자 메시지와 이메일 발신자명
- 소개서, 데모, 발표자료와 포트폴리오
- 향후 도메인, 앱 이름과 상표 출원

한글 대상 화면에서는 `아하루프`를 기본으로 하고, 영문 표기가 필요한 경우 `AHALOOP`를 함께 쓴다.

### 내부 및 기존 자료

- `InsightFlow CRM`은 기존 PRD·폴더·코드·데이터에 남아 있는 레거시 내부 코드명으로만 취급한다.
- 과거 기록과 원본 PRD는 추적 가능성을 위해 이름을 바꾸거나 덮어쓰지 않는다.
- 새 사용자 노출 문구에는 `InsightFlow`를 추가하지 않는다.
- 코드 식별자와 파일명 변경은 별도의 마이그레이션 작업으로 수행하며, 일괄 치환하지 않는다.

## 7. 마스코트 정체성

### 기본 캐릭터

- 종: 흰 족제비
- 성격: 영리하고 다정하며, 필요한 정보를 먼저 발견해 건네는 안내자
- 핵심 표정: 새로운 단서를 찾은 듯한 반짝이는 눈과 작은 미소
- 고유 실루엣: 둥근 머리, 작은 귀, 풍성한 볼, 세 갈래 머리털
- 핵심 행동: 고객에게 맞는 혜택 카드 또는 다음 단계 카드를 두 앞발로 안고 있음

### 브랜드 상징

- 라임색 카드: 검수된 혜택과 선택 가능한 다음 행동
- 흐르는 펄스선: 발견이 준비·신청·수령으로 이어지고 다시 조건 변화를 확인하는 반복
- 네 갈래 반짝임: `아하!` 하고 발견하는 순간

### 마스코트 애칭

`아루`를 작업용 애칭으로 사용할 수 있다. 다만 독립 브랜드명이나 상표로 확정된 것은 아니므로, 별도 검토 전에는 제품명보다 앞세우지 않는다.

## 8. 시각 체계

### 핵심 색상

- Deep Navy: `#0B1325` — 신뢰, 정보의 깊이, 배경
- Flow Mint: `#8BF5D2` — 개인화, 연결, 반짝임
- Action Lime: `#DFFF54` — 선택, 행동, 주간 카드
- Action Ink: `#14200B` 또는 화면 대비에 맞는 짙은 네이비 — 카드 위 펄스와 주요 대비색
- White: `#FFFFFF` — 흰 족제비와 여백

### 이미지 원칙

- 카카오톡 원형 크롭에서 얼굴, 귀, 앞발과 카드가 모두 식별되어야 한다.
- 48픽셀 크기에서도 흰 족제비와 라임 카드가 구분되어야 한다.
- 텍스트, 제3자 로고, 불필요한 장식과 사실적인 사진 배경을 넣지 않는다.
- 기존 상업 캐릭터의 복장, 표정, 실루엣이나 고유 소품을 모방하지 않는다.

## 10. 상표와 저작권 관리

- 2026-09-11 KIPRIS 정확 일치 예비 검색에서 `아하루프`와 `AHALOOP` 결과는 각각 0건이었다.
- 정확 일치 결과가 없다는 사실은 등록 가능성이나 비침해를 보장하지 않는다.
- 외부 출시 또는 유료 서비스 전에는 09·35·42류를 중심으로 발음·외관·관념이 유사한 상표까지 확인한다.
- 마스코트 제작에 사용된 원본 사진의 최초 촬영자와 라이선스는 현재 확인되지 않았다.
- 공개 브랜드의 권리관계를 명확하게 하려면 외부 사진을 입력하지 않은 텍스트 기반 마스코트 원본을 제작하고, 사람이 직접 수정한 레이어 파일과 작업 이력을 보관한다.

## 11. 브랜드 변경 체크리스트

브랜드를 실제 제품에 적용하는 별도 작업에서는 다음을 함께 확인한다.

- 화면 헤더와 사용자 노출 문구
- 페이지 제목과 설명 메타데이터
- 카카오톡 채널명, 프로필과 메시지 템플릿
- 이메일·문자 발신자명과 수신 동의 문구
- 공개 문서, 데모와 발표자료
- 이미지 파일명과 코드 참조
- 테스트 데이터에 남은 레거시 브랜드명
- 도메인과 소셜 계정 사용 가능 여부

기존 PRD, 작업일지, 마이그레이션 기록에서는 과거 명칭을 삭제하지 않는다.

## 12. 완료 기준

아하루프 브랜드 적용은 다음 조건을 충족할 때 완료로 본다.

- 모든 신규 사용자 노출 영역에서 공식 명칭이 일관됨
- 핵심 기능과 데이터 규칙이 기존 PRD와 동일하게 유지됨
- 원형 프로필과 작은 크기에서 마스코트가 식별됨
- 기존 링크·코드·데이터 참조가 깨지지 않음
- 사진 출처, 생성 과정과 사람의 후속 편집 기록이 보관됨
- 출시 범위에 맞는 최종 상표 검토가 완료됨

## 13. 버전 관리

- 브랜드명, 마스코트 핵심 실루엣, 핵심 색상 또는 외부 표기 원칙이 바뀌면 이 문서의 버전을 올린다.
- 기능·데이터·동의·운영 흐름이 바뀌면 기존 제품 PRD의 새 버전 또는 별도 기능 PRD로 관리한다.
- 변경 사항과 실제 검증 결과는 최상위 `작업일지.md`에 함께 기록한다.
