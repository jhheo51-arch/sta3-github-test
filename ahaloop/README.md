# 아하루프 · AHALOOP

> 혜택을 찾는 데서 끝내지 않고, 받기까지 해야 할 일을 줄이는 혜택 회수 서비스

[아하루프 비공개 데모](https://ahaloop.sooyeon-jun-0389.chatgpt.site) · 접속 시 ChatGPT 로그인이 필요합니다.

## 해결하려는 문제

공공 혜택은 여러 기관에 흩어져 있고, 사용자는 검색·반복 입력·자격 해석·서류 준비를 거쳐야 합니다. 아하루프는 혜택 개수를 나열하기보다 `발견 → 조건 확인 → 서류 준비 → 신청 → 승인 → 수령`을 하나의 흐름으로 연결합니다.

## 핵심 제품 원칙

- 지역 → 만 나이 → 생활 상태, 세 번의 선택 안에 첫 혜택을 보여 줍니다.
- 첫 혜택 이후에는 한 화면에서 질문 또는 결정 하나만 요구합니다.
- 맞는 조건, 맞지 않는 조건, 모르는 조건을 분리하고 공식 원문과 확인일을 표시합니다.
- 월간·연간·1회성·비현금 가치를 섞지 않습니다.
- 예상 가치와 실제 자기보고 수령액을 분리합니다.
- 알림 동의, 중복 방지와 조용한 시간을 확인하기 전에는 실제 발송하지 않습니다.

## 첫 외부 검증

- 대상: 서울 거주 만 19~34세 직장인·구직자 중 최근 6개월 안에 정책·지원금 탐색 경험이 있는 5명
- 과제: 마감이 있는 현금성 혜택을 세 번의 선택 안에 확인하고 준비 시작까지 진행
- 관찰: 첫 혜택까지 시간·선택 수, 반복 입력, 중단 지점, 지급 확정 오인 여부
- 경계: 5명 결과는 사용성 문제를 찾기 위한 탐색 증거이며 전체 고객 성과로 일반화하지 않습니다.

## 현재 구현

- 선택형 생활 조건과 아하루프 패스
- 개인화 혜택 브리프와 판정 근거
- 준비·제출·승인·수령 단계 추적
- 공식 원문 수집 및 변경 검수 기록
- 카카오톡·문자 수신 미리보기와 발송 전 안전 검사
- BA 요구 추적, CRM 이벤트, 실험·결정 기록을 모은 검증실
- Cloudflare D1 기반 사용자·혜택·동의·이벤트 저장

## 검증 상태

```bash
npm run harness:pass
```

- 3회 선택 게이트와 한 화면 한 질문 규칙 검사
- 합성 문장 50개, 추가 반례 5개, 판정·금액 규칙 검사
- ESLint와 프로덕션 빌드

합성 검사는 구현 회귀를 막기 위한 것이며 실제 고객 정확도나 전환 성과가 아닙니다.

## 실행

필요 환경: Node.js 22.13 이상

```bash
npm ci
npm run dev
```

로컬 로그인은 `/signin-with-chatgpt?return_to=/`에서 시작합니다. D1 마이그레이션과 배포 절차는 [프로젝트 작업 지침](AGENTS.md)을 따릅니다. 비밀번호, API 키와 실제 고객 개인정보는 저장소에 올리지 않습니다.
