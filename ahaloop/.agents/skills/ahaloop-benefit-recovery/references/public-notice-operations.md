# 공식 공개 공고 운영 기준

2026-09-18 사용자 결정에 따른 구현·검토 기준. 예약 수집·청년몽땅정보통 앱 연결·실발송은 이 문서 작성으로 완료되지 않는다.

## 연결 전 확인

- 출처별 공식 목록/상세 URL, 대상 지역·연령, 이용 조건 근거 URL·확인일, 자동 접근 허용 확인 상태, 허용 빈도, 담당 검수 기준을 남긴다. 공개 열람 가능과 자동 수집·재배포 허용을 동일시하지 않는다. robots 지시도 확인하되 이것만으로 이용 허락을 단정하지 않는다.
- 허용 범위가 불명확하면 예약 수집은 보류하고 수동 확인·공식 링크로 제공한다. 로그인·CAPTCHA·접근 차단을 우회하지 않는다. 사용자 로그인 화면이나 비밀값은 수집 대상으로 삼지 않는다.
- 현재 저장소에 없는 상태·필드는 설계로 표시한다. 연결 허용 여부, 최근 시도/성공, 검수, 예약 가동은 서로 다른 축이며 단일 '연결됨' 표시로 뭉치지 않는다.

## 수집 비용과 오류 줄이기

- 목록에서 후보를 찾고 신규·변경 후보의 상세만 확인한다. 제공되는 ETag/Last-Modified와 캐시를 활용하되 전체 재점검도 계획한다. 페이지 이동·다음 페이지 누락을 테스트한다.
- 429 응답은 Retry-After를 존중하고, 일시적 실패는 간격을 늘려 최대 3회 시도 후 점검 대상으로 남긴다. 401/403·CAPTCHA는 반복 시도하지 않고 해당 출처 수집을 중지한다.
- HTTP 성공만으로 수집 성공 처리하지 않는다. 오류 안내 페이지·빈 본문·필수 항목 누락·비정상 건수 감소는 파싱 실패 또는 검토 필요로 남긴다. 실제 공고 0건과 추출 실패를 구분한다.
- 실패 시 마지막 정상 데이터를 보존하고 마지막 성공일·재확인 필요를 표시한다. 실패를 모집 종료나 데이터 삭제로 해석하지 않는다. 재시도·새로고침으로 동일 발견·알림을 중복 기록하지 않는다.

## 근거와 검수

- 기관 게시일, 아하루프 최초 발견 시각, 최근 확인 시각, 검수 시각을 구분한다. 게시일이 없으면 발견 지연은 미측정이다. 최초 수집한 오래된 공고는 '처음 발견'이지 '오늘 신규 발표'가 아니다.
- 공고 ID/정규화 URL로 원문 중복을 막고, 기관·사업·모집 회차로 다른 사이트의 중복 후보를 묶는다. 제목 유사성만으로 자동 병합하지 않고 지점·지역·회차 차이를 보존한다.
- 원문에서 필드별 근거를 연결한다. PDF·이미지 읽기 실패, 소득 단위, 날짜·시각, 예산 소진, 상충 공고는 미확인으로 검수한다. 개인정보가 포함된 신청자 명단·첨부는 수집하지 않으며 원문 전체 재게시 대신 필요한 사실과 출처를 제공한다.
- 전체 해시 변화는 원문 변경 신호다. 실제 대상·금액·마감·신청 경로 변화인지 검수하기 전 판정 규칙을 바꾸거나 알리지 않는다. 정정 공고는 이전 버전과 관계를 보존한다.
- 저장된 앞 5,000자 발췌에 조건이 없다는 이유로 원문에도 조건이 없다고 판단하지 않는다. 판정에 필요한 문맥·첨부를 확인하지 못하면 미확인으로 남긴다.
- 날짜만 있는 마감에 시간을 지어내지 않는다. 제출·승인·수령된 신청에는 이미 끝낸 행동을 재촉하지 않는다. 승인된 중요 변경만 수신 동의·중복 검사 후 실제 발송 후보가 된다.

## 확대 판단과 점검 사례

- 지역·생활단계별로 등록 출처, 최근 성공 출처, 검수된 공고 범위를 공개한다. 분모를 알 수 없는 전국 누락률을 0%로 표시하지 않는다. 누락은 지정한 공식 목록의 표본 대조로 측정하고 표본 범위를 명시한다.
- 출처 하나의 목록→상세→검수 흐름, 빈 목록/구조 변경/차단/재시도, 정정·중복·새 회차, 날짜만 있는 마감, 미확인 조건을 검증한 뒤 확장한다.
- 수집 성공률, 최신성, 검수 대기시간, 공고당 검수시간을 실제 기록으로 측정한다. 목표·합성 테스트·실제 성과를 분리한다. 기존 코드 테스트와 충돌하면 근거를 확인하고 코드·테스트를 함께 수정한다.

## 역할 분담

- `strategy_research`: 공식 출처·이용 조건·범위 확인. 미확인 접근을 허용으로 판단하지 않는다.
- `ba_review`: 필드 정의·기간 정밀도·중복/회차·미확인 판정의 반례 검토.
- `crm_review`: 사용자 격리·읽음/발견/발송 구분·동의·단계별 중복 억제 검토.
- 메인: 중복 구현 없이 통합·검증·작업일지 유지. 위 역할은 필요 시 위임 기준이지 자동 실행 지시가 아니다. 각 위임에 최신 결정과 파일 소유 범위를 주고 과거 결과를 다시 검증한다.
