# MEMOIVE 제출용 제품 요구사항 정의서

작성일: 2026-10-03  
문서 버전: v1.0 · 기준 구현: 앱 v21  
용도: 수업 제출 및 발표 PPT의 기준 문서

이 문서는 MEMOIVE가 현재 제공하는 기능, 제작자의 선택, 확인된 근거와 남은 검증을 설명합니다. 초기 모바일 앱 구상 전체의 구현 완료를 뜻하지 않습니다. 2026-09-14 초기 PRD는 보존하며, 현재 범위와 발표 내용은 이 문서를 우선합니다.

## 제품 정의

**흘러가는 정보를 영감으로, 영감을 결과물로.**

MEMOIVE는 저장한 콘텐츠에 자신의 생각을 덧붙이고, 필요한 순간 다시 찾아 수정 가능한 결과물로 발전시키는 모바일 중심 웹 시제품입니다. 북마크 저장 개수보다 기록이 실제 글·기획안의 재료가 되는 흐름을 지향합니다.

장기 목표는 어떤 입력 형식이든 이해하고 창작을 돕는 개인 창작 시스템입니다. 현재 제출 범위는 **텍스트 또는 접근 가능한 공개 링크 저장 → 내 생각 → 단어 검색 → 초안 편집 → 결과물 저장·재열기**입니다. iOS·Android 앱스토어용 네이티브 앱이나 운영 검증을 마친 AI 에이전트는 아닙니다.

## 문제와 초기 사용자

문제 가설은 “콘텐츠를 저장해도 저장한 이유를 잊고, 필요한 순간 다시 찾거나 실제 작업에 활용하기 어렵다”입니다. 정보 과잉 자체를 해결하기보다, 저장 이후의 단절에 집중합니다.

초기 사용자는 제품 사례와 레퍼런스를 모아 기획안·포트폴리오를 만드는 PM/PO 및 컨설팅 직무 준비자입니다. 제작자의 관심과 사용 맥락에서 출발한 선택이며, 인터뷰나 시장 조사로 이 집단의 대표 수요를 확인한 것은 아닙니다. 초기 PRD의 폭넓은 연령·직업 범위를 이번 제출에서는 좁혔습니다.

대표 상황은 글을 읽다가 발견한 생각을 남기고, 다음 날 비슷한 문제를 다루는 기획안에 참고하는 것입니다. 직업을 고정하는 대신 기획자·마케터·연구자·일상 관점의 질문을 선택할 수 있습니다.

## 가설과 차별화 방향

제품 가설: 콘텐츠의 요약과 저장 이유를 함께 보존하고, 그 기록을 결과물 편집에 연결하면 저장과 활용 사이의 수고를 줄일 수 있다.

현재 설계상 차이는 다음 세 가지입니다.

- 원문 요약과 내 생각을 구분하고 결과물에서도 참고 기록을 연결합니다.
- 결과물을 만든 뒤 다시 열어 편집하고 실제 활용 근거를 남길 수 있습니다.
- 예시 자료와 사용자의 기록을 구분해 분석합니다.

이는 구현 방향이지 경쟁 서비스 대비 우월성이나 효과 입증이 아닙니다. 다른 북마크·메모 도구와의 직접 비교 실험은 아직 없습니다.

## 핵심 사용자 흐름

1. 텍스트를 입력하거나 공개 링크와 메모를 넣습니다. 링크를 읽지 못하면 주소와 메모를 보존하고 재시도할 수 있습니다.
2. 내 생각을 덧붙입니다. 입력을 강제하지 않으며 나중에 작성하거나 결과물로 바로 이동할 수 있습니다.
3. 기록 목록에서 기억나는 단어로 검색합니다. 주제별 모아보기와 월별 달력도 제공합니다.
4. 결과물 만들기에서 참고 기록, 결과물 종류, 전달 목적, 관점을 선택·입력합니다.
5. 양식 기반 기본 초안을 만들고 제목과 본문을 직접 수정합니다.
6. 결과물을 저장한 뒤 창작 메뉴에서 다시 엽니다. 필요하면 복사·공유 이미지로 내보냅니다.
7. 실제 사용했다면 사용 여부와 근거를 선택적으로 남깁니다. 저장·다운로드만으로 실제 활용 완료로 계산하지 않습니다.

## 화면 구성과 사용 원칙

하단 메뉴는 오늘·기록·기록하기·창작·달력입니다. 주제별 분류는 유지되며 창작 메뉴가 이를 대체하지 않습니다. 상단 분석과 설정에서 분석·관점·알림·백업·설치 안내로 접근합니다.

커피색과 밝은 배경을 유지하고, 기록 상세·창작 입력 및 사례 목록의 가독성을 정리했습니다. 작은 아이콘과 충분한 터치 영역을 구분합니다. 기록 상세에서 결과물 만들기를 중심 행동으로, 정리본 복사를 보조 행동으로 둡니다.

v21은 스크롤 막대 표시만 숨기며 휠·터치·키보드 이동을 유지합니다. 실제 휴대폰, 화면 읽기 도구, 최대 확대 등 전체 접근성 검증은 끝나지 않았습니다.

## 기술 구조와 데이터 보호

정적 HTML·CSS·JavaScript 화면과 브라우저 저장으로 기본 흐름이 동작합니다. 서비스 워커는 설치와 일부 오프라인 자산 사용을 돕지만 모든 외부 기능의 오프라인 동작을 보장하지 않습니다.

공개 링크의 본문은 Jina AI Reader로 요청하며 URL이 외부로 전송됩니다. 비공개 문서·인증 정보가 담긴 주소는 입력하지 않습니다. 외부 글은 자신의 결과물과 구분하고 원문 출처를 유지합니다.

앱 기록과 사용 테스트 기록은 별도로 보관되므로 각각 백업합니다. 다른 기기나 브라우저에는 자동으로 나타나지 않으며, 브라우저 데이터 삭제·저장 공간 부족으로 기록을 잃을 수 있습니다. 저장 실패·장기 대량 사용의 전수 검증은 남아 있습니다.

Cloudflare Workers·Gemini는 준비된 확장 경로입니다. 실제 도입 전 인증·서버 측 사용량 제한·전송 동의·오류 복구·비용과 프로젝트별 실제 한도를 확인해야 합니다. 특정 모델의 무료 제공이나 요청 횟수가 확정되었다고 발표하지 않습니다. API 키는 공개 코드와 브라우저 코드에 넣지 않습니다.

## 측정과 성공 판단

현재 분석은 사용자 개인의 브라우저 관찰입니다. 외부 고객 모집단의 수요나 유지율이 아닙니다. 기본 예시는 집계에서 제외합니다.

| 항목 | 현재 의미 | 해석 주의 |
| --- | --- | --- |
| 다시 본 기록 비율 | 직접 상세를 연 기록 수 ÷ 예시 제외 기록 수 | 다음 날 재방문율과 다름 |
| 생각 작성 비율 | 생각이 있는 기록 수 ÷ 예시 제외 기록 수 | 생각의 품질을 측정하지 않음 |
| 결과물 전환 비율 | 결과물에 연결된 고유 기록 수 ÷ 예시 제외 기록 수 | 실제 사용 완료와 다름 |
| 실제 활용 결과물 | 내 기록을 포함하고 사용 표시·근거가 있는 결과물 수 | 사용자의 자기 보고 |
| 요약 도움 비율 | 도움이 됐다고 평가한 기록 수 ÷ 평가한 기록 수 | 현재 정리 기능에 대한 평가, 외부 AI 정확도가 아님 |
| 과제 완료·시간 | 같은 과제·방식·버전의 수행 결과와 도움 없이 완료한 회차의 시간 | 반복 학습 효과·콘텐츠 난이도 차이 존재 |

사건 기록은 최근 2,000개 범위로 제한되므로 장기 전체 이력을 뜻하지 않습니다. 목표 효과 수치나 만족도를 임의로 채우지 않습니다.

| 아이콘·사례 카드·입력 안내가 과도하거나 읽기 어려움 | 아이콘 축소, 사례 카드와 글꼴·안내 크기 조정 | 이전 브라우저 검사 기록 존재, 사용자의 개선 후 체감은 별도 |
| 스크롤바가 계속 노출됨 | 표시만 숨김 | 이전 시험에서 PageDown 이동 유지 확인 |

자동 검사 4종은 검색·보존·집계, 이전 대비 회귀, 사례·활용 근거, 최신순·메뉴를 다룹니다. 최신 실행 결과와 화면 검사 범위는 기술 점검 문서에 기록합니다. 기존 브라우저 시연 기록과 이번 검사 결과를 구분합니다.

## 실제 사용 검증 계획

현재 확인된 제출 문서에는 제작자의 실사용 효과 결과가 없습니다. 사용자가 이미 사용했더라도 근거를 받기 전에는 완료로 채우지 않습니다.

제작자 1명이 실제 콘텐츠로 3~5회 시험하는 것은 시작 방법이지 통계적 검증 기준이 아닙니다. 같은 사람의 5회 사용을 참여자 5명으로 계산하지 않습니다.

첫날 기록과 생각을 남기고, 최소 30분 뒤 또는 다음 날 기억나는 개념으로 다시 찾아 결과물에 활용합니다. 과제·버전·기기·성공 여부·도움 여부·소요시간·막힌 위치·활용한 결과물을 남깁니다. 반복 문제 하나를 개선한다면 같은 과제를 다시 수행하고 조건 차이와 학습효과를 명시합니다.

완료 기준은 “저장 버튼을 눌렀다”가 아니라 **결과물을 다시 열었을 때 작성한 문장과 연결된 참고 기록이 있고, 실제 활용 근거를 설명할 수 있다**입니다. 외부 사용자 첫 사용성·수요·차별화 검증은 후속 단계입니다.

## 제출과 시연

공개 제출 저장소는 [sta3-github-test](https://github.com/jhheo51-arch/sta3-github-test)이며 제품 파일은 memoive 폴더에 있습니다. 사용자의 운영 사이트는 소유자 전용 비공개입니다. 공개 코드 제출과 공개 사이트 운영은 다릅니다.

평가자는 README의 방법으로 실행할 수 있습니다. 발표는 외부 사이트 오류에 영향을 받지 않는 텍스트 경로를 기본으로 하고, 공개 링크는 보조 시연으로 둡니다. 가상 시연을 실제 사용자 성과라고 설명하지 않습니다.

발표 자료는 다음 순서를 권장합니다.

1. 문제와 대상 사용자
2. 기존 저장 방식에서 느낀 문제 가설과 선택 이유
3. 기록에서 결과물까지 핵심 흐름
4. 실제 화면 시연
5. 우선한 기능과 제외한 기능
6. 확인된 기술 개선 전후
7. 실사용 결과가 있으면 근거와 한계, 없으면 계획과 미검증 표시
8. 현재 한계·다음 검증·공개 저장소

AI를 활용한 제작 과정과 서비스 내부 AI 기능은 구분합니다. 제작자는 브랜드·제품 방향·모바일 경험·기록 리듬·가독성 개선을 요청하고 판단했습니다. Codex는 코드·문서·기술 시험을 보조했습니다. MEMOIVE 내부 Gemini 호출은 아직 연결되지 않았습니다.

## 남아 있는 제품 과제

실사용 효과만 남은 것은 아닙니다. 입력 형식별 안정성, 결과물의 내용 품질, 외부 AI 연결, 장기 데이터 보존, 실제 기기 접근성, 경쟁 도구 대비 가치와 외부 사용자 수요가 남아 있습니다.

제출 준비와 제품 완성을 분리합니다. 현재 범위의 재현성과 정직한 설명을 갖춰 제출하고, 실사용에서 반복되는 막힘을 기준으로 다음 기능을 선택합니다. AI 연결이나 기능 추가만으로 제품 가치가 증명되지는 않습니다.
