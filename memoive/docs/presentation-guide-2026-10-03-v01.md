# MEMOIVE 발표 구성과 시연 대본

2026-10-03 · 앱 v21 기준. PPT 자체가 아니라 발표 제작을 위한 자료입니다.
제품 정의와 범위는 [최신 PRD](PRD_MEMOIVE_2026-10-03-v01.md)를 기준으로 합니다.

## 발표의 중심 문장

“저장한 콘텐츠를 잊지 않도록 내 생각을 붙이고, 다시 찾아 기획 결과물에 연결하는 흐름을 만들었습니다.”

모든 자료를 AI가 이해한다거나 고객 만족도가 검증됐다고 설명하지 않습니다.

## 8장 발표 구성

| 장 | 제목 | 전달할 내용 | 보여줄 근거 |
| --- | --- | --- | --- |
| 1 | 저장에서 활용으로 | MEMOIVE 정의와 문제 가설 | 홈 화면과 핵심 문장 |
| 2 | 누구의 문제인가 | PM/PO·컨설팅 준비자로 좁힌 이유 | PRD의 대상 선택과 아직 인터뷰 전이라는 한계 |
| 3 | 어떻게 해결하는가 | 저장·생각·검색·결과물 연결 | 4단계 화면 또는 짧은 시연 |
| 4 | 실제로 작동하는 흐름 | 아래 가상 자료로 재현 | 저장·검색·편집·재접속 화면 |
| 5 | 무엇을 선택하고 제외했는가 | 단어 검색·양식 초안·로컬 저장의 이유와 비용 | PRD 의사결정 표에서 3개 선택 |
| 6 | 어떻게 개선했는가 | 검색 누락·예시 집계·출처 혼합 수정 | 기술 점검 문서의 고정 자료 전후 비교 |
| 7 | 어디까지 검증했는가 | 기술 검사와 실사용 효과 구분 | 자동 검사 결과, 실사용 결과는 확보한 경우에만 |
| 8 | 다음 단계 | 실사용 관찰 → 반복 문제 수정 → 외부 사용자 검증 | 남은 과제와 공개 저장소 주소 |

발표 시간에 맞춰 2~3분 시연을 포함합니다. 대본을 그대로 읽기보다 본인이 왜 선택했는지를 자신의 말로 설명합니다.

## 개인정보 없는 3분 시연

아래 문장은 외부 기사 인용이나 실제 고객 관찰이 아닌 **발표용 가상 자료**입니다. 운영 개인 기록과 섞지 않도록 로컬 실행 주소 또는 별도 브라우저 프로필을 사용합니다.

입력 텍스트:
> 발표용 가상 기록입니다. 기획 참고 자료를 저장할 때 나중에 활용할 장면을 한 줄 적는다. 예를 들어 첫 화면 개선안을 만들 때 다시 찾아볼 수 있도록 검색 단서를 남긴다.

내 생각:
> 재탐색단서라는 단어로 다시 찾아 첫 화면에 결과물 예시를 보여주는 제안에 연결하자.

진행:
1. 무엇이든 기록하기 → 텍스트에 위 내용을 입력하고 내 생각을 함께 저장합니다.
2. 기록에서 “재탐색단서”를 검색해 방금 저장한 기록을 엽니다.
3. 결과물 만들기 → 업무 제안서를 고릅니다.
4. 목적은 “첫 화면에서 기록의 활용 방법을 설명하기”, 관점은 “사용자가 저장 뒤 어떤 결과를 만들 수 있는지 예시 한 개로 보여주자”로 입력합니다.
5. 기본 초안을 만들고 제목을 “발표용 가상 첫 화면 개선안”으로 바꿉니다.
6. 본문에 “첫 화면에 저장부터 결과물까지 이어지는 예시 하나를 배치하고 이해 여부를 다음 시험에서 확인한다”를 직접 추가합니다.
7. 나의 결과물로 저장 → 창작에서 다시 열기 → 새로고침 후 같은 제목·문장·참고 기록이 남는지 확인합니다.

마무리 발언:
“현재 초안은 AI 완성 글이 아니라 양식 기반입니다. 원문과 내 의견을 분리하고 사람이 편집·저장할 수 있게 했습니다.”

기록 저장 자체가 실패하면 브라우저 저장 허용 여부를 확인합니다. 링크 본문이 막히면 원문을 읽었다고 주장하지 말고 확보한 텍스트 경로를 사용합니다. 비공개 자료나 API 키를 발표하지 않습니다.

## 시연 영상 또는 화면 자료 준비

영상은 아직 녹화된 것으로 간주하지 않습니다. 녹화한다면 3분 시연 순서를 따르고 브라우저 계정·알림·개인 메모를 가립니다. 영상이 없다면 실행 시연과 동일 단계의 화면 자료를 사용합니다. 비공개 사이트 링크만으로 평가자가 접속할 수 있다고 안내하지 않습니다.

[가상 시연의 결과물 보존 화면](memoive-demo-preserved-2026-10-03-v01.png)을 PPT에 사용할 수 있습니다. 2026-10-03 Codex의 기능 시험이며, 제작자나 고객의 실제 사용 성과를 보여주는 화면은 아닙니다.

## 실제 사용 근거 작성 양식

이 항목은 사용자가 실제 경험한 후에 작성합니다. 빈 항목을 가상 값으로 채우지 않습니다.

- 수행 날짜와 앱 버전:
- 실제 활용하려던 일:
- 사용한 콘텐츠와 출처:
- 저장 후 다시 찾기까지 경과시간:
- 검색어와 막혔던 화면:
- 도움 없이 완료 / 도움 후 완료 / 실패 / 중단:
- 과제 수행시간:
- 저장한 결과물과 실제 사용한 문장:
- 무엇을 바꾸기로 판단했는가:
- 변경 후 같은 과제를 수행한 결과:
- 조건 차이와 아직 알 수 없는 것:

혼자 반복 사용한 결과는 제작자 1명의 관찰입니다. 시간 차이만으로 제품의 효과를 확정하지 않습니다. 공개할 때 원문 전체·개인정보를 제거하고 필요한 관찰만 요약합니다.

## 예상 질문과 정직한 답변

- 왜 기존 메모앱이 아닌가: 기록과 결과물 사이의 연결을 한 흐름으로 설계했으며, 기존 도구보다 낫다는 비교 검증은 남아 있습니다.
- AI가 어디에 쓰이는가: 제작 과정에 Codex를 활용했습니다. 제품의 기본 초안은 규칙·양식 기반이며 Gemini 연동 코드는 준비됐지만 현재 실호출은 연결 전입니다.
- 실제 사용자는 몇 명인가: 확인된 외부 사용자 연구는 없습니다. 본인 시험 결과가 생기면 제작자 1명, 실제 회차 수로 정확히 말합니다.
- 모바일 앱인가: 모바일 중심 웹앱입니다. 지원 환경의 설치·공유 기능은 있으나 앱스토어 네이티브 앱은 아닙니다.
- 데이터는 어디 있는가: 현재 브라우저에 보관합니다. 계정 동기화는 없고 앱 기록과 시험 기록을 각각 백업해야 합니다.
- 자동으로 인스타그램에 올라가는가: 아닙니다. 공유 이미지 저장과 지원 기기의 공유 메뉴를 제공하며 게시 여부는 사용자가 결정합니다.
