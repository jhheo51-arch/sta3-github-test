# MEMOIVE 최종 PRD

> 어떤 형태로 건네도, 내 기록으로 살아나게  
> Product Requirements Document v0.3 Final  
> 작성일: 2026-09-14  
> 대상 제품: iOS·Android 모바일 앱  
> 문서 상태: 제품 정의 및 MVP 범위 확정

## 1. 제품 정의

### 브랜드

**MEMOIVE / 메모이브**

- 합성 의미: `Memo + Alive`
- 브랜드 의미: 흩어진 자료와 생각을 다시 살아 움직이는 기록으로 만든다.
- 슬로건: **어떤 형태로 건네도, 내 기록으로 살아나게.**

### 한 줄 소개

공유 메뉴, 링크, 스크린샷, 이미지, 텍스트, 음성 등 어떤 형태의 자료든 보내면 AI가 내용을 알아서 이해하고 일관된 형식으로 요약·분류·기록하며, 사용자는 그 위에 나만의 생각을 자유롭게 덧붙일 수 있는 모바일 기록 앱.

### 제품의 핵심 구조

`무엇이든 입력 → 형식 자동 판별 → 내용 추출 → AI 정리 → 표준 기록 생성 → 나만의 기록 추가 → 연결·재발견·활용`

### 핵심 명제

> 정보가 부족한 것이 아니라, 너무 많은 정보를 내 것으로 남기지 못하는 것이 문제다.

## 2. 배경과 해결할 문제

사용자는 기사, YouTube, SNS 게시물, 이미지 레퍼런스, 스크린샷, 음성 아이디어 등 수많은 정보를 매일 접한다. 하지만 자료마다 저장 방법이 다르고, 북마크·사진첩·메모 앱·나에게 보내기에 흩어진다.

결과적으로 다음 문제가 발생한다.

1. 콘텐츠를 발견한 순간 직접 정리할 시간이 없다.
2. 입력 형식마다 다른 앱과 저장 방법을 사용해야 한다.
3. 링크나 스크린샷만 저장하면 왜 중요했는지 잊는다.
4. AI 요약만 남으면 내용은 보존되지만 사용자의 생각은 보존되지 않는다.
5. 기록 형식이 달라 검색과 비교가 어렵다.
6. 저장한 자료가 다시 나타나지 않아 실제 일과 창작에 활용되지 않는다.
7. 매일 긴 글을 써야 한다는 부담 때문에 기록을 포기한다.

### 문제 해결 가설

사용자가 어떤 형태의 자료든 한곳으로 보낼 수 있고, MEMOIVE가 이를 자동으로 이해해 같은 구조의 기록으로 만들어준다면 기록 부담이 크게 줄어들 것이다.

여기에 부담 없는 질문 하나로 사용자의 생각을 남기게 하고, 과거 기록을 적절한 시점에 다시 보여준다면 단순 저장물이 개인의 지식과 창작 재료로 발전할 것이다.

## 3. 목표 사용자

### 1차 사용자

- 20~39세 기획자, 디자이너, 마케터, 창작자, 연구자, 학습자
- 기사, 영상, SNS, 이미지 레퍼런스를 자주 수집함
- 북마크, 스크린샷, 메모가 여러 앱에 흩어져 있음
- 기록 욕구는 높지만 정리와 분류를 번거롭게 느낌
- 저장한 자료를 업무, 글쓰기, 콘텐츠 제작에 다시 활용하고 싶어 함

### 대표 사용자 상황

> 출퇴근 중 YouTube에서 좋은 인터뷰를 발견했다. 지금은 정리할 시간이 없지만 공유 메뉴로 MEMOIVE에 보낸다. 앱은 영상 자막을 분석해 핵심 내용을 기록하고, 저녁에 “이 인터뷰에서 가장 기억하고 싶은 관점은 무엇인가요?”라고 묻는다. 사용자는 음성으로 한 문장을 남긴다. 한 달 뒤 새로운 프로젝트를 시작할 때 이 기록과 관련 이미지 레퍼런스가 함께 다시 나타난다.

### 사용자가 해결하려는 일

> 좋은 콘텐츠나 레퍼런스를 발견했을 때 형식과 장소를 고민하지 않고 빠르게 저장하고, 나중에 기억하고 활용할 수 있도록 내용과 내 생각을 함께 남기고 싶다.

## 4. 제품 목표와 비목표

### 사용자 목표

- 어떤 형태의 자료도 10초 안에 저장한다.
- 긴 콘텐츠의 핵심을 빠르게 파악한다.
- 저장한 이유와 나의 생각을 한 문장으로 남긴다.
- 형식이 다른 기록을 하나의 주제에서 함께 찾는다.
- 과거 기록을 필요한 순간 다시 발견한다.
- 기록을 글, 아이디어, 프로젝트에 활용한다.

### 제품 목표

- 모든 입력을 하나의 표준 기록 구조로 통합한다.
- AI 정리와 사용자 기록을 명확히 구분한다.
- 저장 실패보다 원본 보존을 우선한다.
- 사용자가 기록을 완성하도록 강요하지 않는다.
- 저장량보다 기록의 재활용을 높인다.

### 하지 않는 것

- 새로운 콘텐츠를 끝없이 추천하는 피드
- AI가 사용자의 생각까지 대신 작성하는 서비스
- 공개 팔로우·좋아요 중심의 소셜 서비스
- 매일 접속을 강요하는 출석 앱
- 팀 문서 관리와 협업 중심 도구

## 5. 핵심 가치 제안

### 1. 무엇이든 받는다

사용자는 입력 형식에 맞는 앱을 고를 필요가 없다. 공유 메뉴, 링크, 스크린샷, 이미지, 텍스트, 음성을 모두 MEMOIVE에 보낸다.

### 2. 알아서 이해한다

MEMOIVE는 입력 형식을 자동 판별하고 필요한 처리 방법을 선택한다.

- 링크: 본문과 기본 정보 추출
- YouTube: 자막과 영상 정보 분석
- 스크린샷·이미지: 화면 내용 설명과 문자 추출
- 텍스트: 핵심 내용과 주제 분석
- 음성: 글자로 변환한 뒤 핵심 내용 정리

### 3. 같은 형식으로 기록한다

서로 다른 입력도 `원본 → AI 정리 → 나의 기록 → 연결과 활용`이라는 동일한 구조로 저장한다.

### 4. 내 생각을 더한다

사용자는 저장 시점 또는 나중에 텍스트와 음성으로 자신의 생각을 추가한다. AI는 사용자의 생각을 대신 만들지 않고, 생각을 꺼내기 위한 질문 하나를 제안한다.

### 5. 다시 꺼내 쓴다

기록은 저장으로 끝나지 않는다. 현재 관심사와 관련된 과거 기록을 다시 보여주고, 여러 기록을 연결해 글과 프로젝트의 재료로 발전시킨다.

## 6. 경쟁 서비스와의 차별점

### 일반적인 AI 지식관리 서비스

`저장 → AI 요약 → 자동 분류 → 검색 또는 대화`

### MEMOIVE

`무엇이든 전달 → 자동 이해 → 표준 기록 → 나의 생각 → 연결 → 재발견 → 활용`

### 핵심 차별점

1. **범용 입력** — 콘텐츠 형식별 도구를 나누지 않고 하나의 기록 입구를 제공한다.
2. **사용자 기록 우선** — AI 요약보다 사용자가 직접 남긴 생각을 기록 상세 상단에 보여준다.
3. **질문하는 AI** — 답을 대신 만드는 것이 아니라 사용자의 관점과 경험을 끌어낸다.
4. **점진적 기록** — 발견 순간에는 원본만 저장하고 나중에 생각과 연결을 추가할 수 있다.
5. **생각의 변화 기록** — 같은 주제에 대해 과거와 현재에 남긴 생각을 비교한다.
6. **재발견과 활용** — 저장 자료를 글감, 프로젝트 자료, 실행 아이디어로 발전시킨다.

## 7. 제품 원칙

1. **입력을 가리지 않는다** — 형식의 차이는 시스템이 처리한다.
2. **저장을 멈추게 하지 않는다** — 저장 시 필수 입력을 최소화한다.
3. **원본을 먼저 지킨다** — AI 분석이 실패해도 사용자가 준 자료는 보존한다.
4. **한 문장이면 충분하다** — 짧은 생각도 완전한 기록으로 인정한다.
5. **AI와 나를 구분한다** — AI 생성 내용과 사용자 작성 내용을 시각적으로 구분한다.
6. **알림은 재촉이 아니라 계기다** — 죄책감 대신 답하기 쉬운 질문을 건넨다.
7. **저장보다 재활용을 측정한다** — 얼마나 많이 모았는지보다 다시 꺼내 썼는지를 본다.

## 8. 통합 입력 설계

### 입력 방법

| 입력 경로 | 사용 상황 | 기본 동작 |
|---|---|---|
| 모바일 공유 메뉴 | 브라우저, YouTube, SNS, 사진 앱 사용 중 | MEMOIVE 선택 후 즉시 저장 |
| 링크 붙여넣기 | 복사한 주소가 있을 때 | 주소 분석 후 저장 |
| 스크린샷·이미지 | 디자인·문구·화면 레퍼런스 | 이미지 설명과 문자 추출 |
| 텍스트 입력 | 문장, 인용, 갑자기 떠오른 생각 | 핵심 정리와 주제 추천 |
| 음성 입력 | 이동 중 또는 타이핑이 어려울 때 | 음성을 글자로 변환 후 정리 |
| 앱의 `+ 기록` | 앱 안에서 새 기록 시작 | 입력 방식 선택 |
| 홈 화면 위젯 | 앱을 열지 않고 빠른 기록 | 선택한 입력 방식으로 바로 이동 |

### 입력 자동 판별

시스템은 주소 형태와 서비스, 파일 형식, 이미지 포함 여부, 음성 형식, 공유한 앱, 입력된 텍스트의 구조를 기준으로 유형을 판별한다.

판별 결과가 불확실해도 저장을 막지 않는다. 우선 `기타 자료`로 저장한 뒤 사용자가 유형을 수정할 수 있다.

### 유형별 처리

#### 웹 기사·블로그

1. 제목, 작성자, 출처, 발행일, 대표 이미지 추출
2. 본문에서 메뉴와 광고 제거
3. 한 줄 핵심과 핵심 내용 생성
4. 출처와 원문 주소 유지

#### YouTube

1. 영상 제목, 채널, 길이, 대표 이미지 추출
2. 자막이 있으면 내용을 시간 정보와 함께 분석
3. 주요 내용과 기억할 구간 생성
4. 자막이 없으면 링크와 사용자 메모를 우선 저장

#### SNS·일반 링크

1. 공개적으로 접근 가능한 제목과 설명 추출
2. 접근 범위 안에서만 요약
3. 접근이 제한되면 추측하지 않고 사용자 메모를 중심으로 기록

#### 스크린샷·이미지

1. 이미지 속 문자 추출
2. 주요 대상, 구조, 색상, 맥락 설명
3. 디자인·문구·제품·자료 등 레퍼런스 유형 추정
4. 원본 이미지를 기록에 유지

#### 텍스트

1. 원문 그대로 보존
2. 핵심 문장과 주제 제안
3. 인용인지 사용자 생각인지 확인할 수 있도록 출처 입력 선택 제공

#### 음성

1. 음성 원본 보존
2. 글자로 변환
3. 핵심 내용과 할 일 후보 정리
4. 사용자가 변환된 내용을 수정할 수 있게 제공

## 9. 표준 기록 구조

모든 입력은 같은 네 부분으로 저장한다.

### A. 사용자가 준 원본

- 원문 링크, 이미지, 텍스트 또는 음성
- 제목
- 작성자·채널·출처
- 발행일 또는 생성일
- 콘텐츠 유형
- 저장일

### B. MEMOIVE가 정리한 기록

- 한 줄 핵심
- 핵심 내용 최대 3개
- 기억할 만한 근거, 장면 또는 구간
- 확인이 필요한 내용
- 추천 주제
- 관련 기록과 연결 이유

### C. 나만의 기록

- 저장한 이유
- 가장 인상적인 점
- 동의하거나 다르게 생각한 점
- 기존 경험과의 연결
- 활용하고 싶은 곳
- 자유로운 텍스트·음성 메모

사용자는 위 항목을 모두 작성할 필요가 없다. 한 줄 또는 음성 하나만 남겨도 된다.

### D. 연결과 활용

- 관련된 과거 기록
- 연결된 주제
- 프로젝트 또는 아이디어 묶음
- 이후 할 일
- 글쓰기·기획 자료로 사용한 이력

## 10. AI의 역할과 경계

### AI가 하는 일

- 입력 형식 판별
- 문자·음성·본문 추출
- 핵심 내용 요약
- 기존 주제를 우선한 분류 제안
- 비슷한 과거 기록 연결
- 사용자 생각을 돕는 질문 하나 제안
- 원문 접근 범위와 불확실성 표시

### AI가 하지 않는 일

- 사용자의 생각을 임의로 만들어 작성
- 사용자의 원문을 알리지 않고 수정
- 원문에 없는 사실, 수치, 인용 생성
- 낮은 가치의 콘텐츠라고 단정해 저장 차단
- 기존 사용자 기록을 덮어쓰기
- 접근하지 못한 콘텐츠를 본 것처럼 요약

### 기본 AI 출력

```text
1. 입력 유형과 처리 범위
2. 한 줄 핵심: 120자 이내
3. 핵심 내용: 최대 3개
4. 기억할 근거·장면·구간: 최대 2개
5. 확인할 점: 불확실하거나 접근하지 못한 내용
6. 추천 주제: 기존 주제 우선, 최대 3개
7. 관련 기록: 연결 이유와 함께 최대 3개
8. 사용자 질문: 판단·경험·연결·활용을 묻는 질문 1개
```

## 11. 나만의 기록 경험

### 입력 시점

- 자료를 처음 저장할 때
- AI 정리를 확인한 뒤
- 질문형 알림을 열었을 때
- 과거 기록을 다시 발견했을 때
- 나중에 생각이 달라졌을 때

### 입력 방식

- 한 줄 텍스트
- 긴 자유 메모
- 음성
- 인상·동의·반박·활용 중 빠른 선택
- 원문의 특정 장면 또는 문장에 붙이는 메모

### 표시 원칙

- 기록 상세 화면의 첫 번째 내용으로 `나의 한 줄`을 보여준다.
- AI 정리는 별도의 표시와 영역을 사용한다.
- 사용자가 여러 시점에 남긴 생각을 시간순으로 보존한다.
- AI가 문장을 다듬더라도 사용자가 작성한 원문을 확인할 수 있다.

## 12. 핵심 사용자 흐름

### 흐름 1: 공유 메뉴로 즉시 저장

1. 사용자가 다른 앱에서 콘텐츠를 발견한다.
2. 공유 버튼을 누르고 MEMOIVE를 선택한다.
3. 원본 미리보기와 선택 입력 `왜 남기고 싶나요?`가 표시된다.
4. 사용자는 메모 없이 즉시 저장하거나 한 줄을 추가한다.
5. 원본이 먼저 저장되고 AI 분석은 이어서 진행된다.
6. 저장 완료 후 원래 사용하던 앱으로 돌아간다.

**목표:** 공유 시작부터 저장 완료까지 10초 이내

### 흐름 2: 앱 안에서 무엇이든 기록

1. 사용자가 `+ 기록`을 누른다.
2. 링크, 이미지, 텍스트, 음성 중 하나를 선택한다.
3. 시스템이 입력 형식을 자동 판별한다.
4. 원본을 저장하고 AI 정리를 생성한다.
5. 질문 하나를 보여준다.
6. 사용자는 답하거나 나중으로 미룬다.

### 흐름 3: 저장한 기록 완성

1. 사용자가 `이어 쓸 기록`을 연다.
2. 원본과 AI 정리를 확인한다.
3. 콘텐츠에 맞는 질문 하나에 답한다.
4. 관련 주제와 과거 기록을 확인한다.
5. 나만의 기록이 추가되면 `생각이 담긴 기록` 상태가 된다.

### 흐름 4: 과거 기록 재발견

1. 현재 관심 주제와 관련된 과거 기록이 오늘 화면에 나타난다.
2. 사용자가 당시의 나만의 기록을 확인한다.
3. `지금은 어떻게 생각하나요?`에 새 생각을 남긴다.
4. 생각의 변화를 시간순으로 확인한다.

### 흐름 5: 기록 활용

1. 사용자가 관련 기록을 여러 개 선택한다.
2. `활용하기`를 누른다.
3. 글감 정리, 프로젝트 레퍼런스, 실행 아이디어 중 하나를 고른다.
4. AI가 원본 출처와 사용자 생각을 구분해 초안을 만든다.
5. 사용자가 편집하거나 내보낸다.

## 13. 질문형 기록 리듬

### 역할

주기적 알림은 상시 기록을 대체하지 않는다. 사용자가 이미 저장한 자료에 생각을 더하거나 과거 기록을 다시 활용하도록 돕는 보조 장치다.

### 기본 설정

- 추천 빈도: 주 3회
- 사용자가 요일과 시간 변경 가능
- 매일, 주 1회, 주 3회, 주말 정리, 끄기 제공
- 첫 기록을 완료한 후 알림 허용 여부 요청

### 알림 대상 우선순위

1. 저장했지만 나만의 기록이 없는 자료
2. 사용자가 다시 보기로 표시한 자료
3. 현재 관심 주제와 연결되는 과거 기록
4. 생각이 달라졌을 가능성이 있는 오래된 기록

### 메시지 예시

| 상태 | 메시지 |
|---|---|
| 오늘 기록 없음 | 오늘 마음에 남은 내용을 한 문장으로 기록해볼까요? |
| 미완성 기록 있음 | 어제 저장한 ‘콘텐츠 제목’, 왜 마음에 남았나요? |
| 주간 리듬 진행 | 이번 주 두 번째 기록, 한 문장이면 충분해요. |
| 과거 기록 연결 | 한 달 전 기록이 오늘의 ‘디자인’ 주제와 연결돼요. |
| 오랜만에 복귀 | 놓친 기록을 채울 필요 없어요. 오늘부터 다시 시작해요. |

### 보내지 않는 조건

- 사용자가 오늘 이미 기록한 경우
- 최근 알림을 연속으로 무시한 경우
- 사용자의 방해 금지 시간
- 분석 실패 기록만 남은 경우
- 사용자가 숨긴 기록인 경우

### 진행 표현

- 연속 일수보다 `이번 주 2/3`을 기본으로 보여준다.
- 한 주를 놓쳐도 누적 기록과 이전 성취를 유지한다.
- 손실과 죄책감을 자극하는 문구를 사용하지 않는다.

## 17. 기능 요구사항과 완료 기준

### 저장

- 지원되는 모든 입력을 로그인 이후 어느 화면에서나 저장할 수 있어야 한다.
- 공유 메뉴 저장은 일반적인 네트워크에서 10초 안에 완료되어야 한다.
- AI 분석보다 원본 저장이 먼저 완료되어야 한다.
- 분석 실패가 원본과 사용자 메모 삭제로 이어져서는 안 된다.
- 중복 자료에는 기존 기록에 새 생각 추가와 별도 맥락 저장을 모두 제공해야 한다.

### 자동 이해와 요약

- 입력 유형과 처리 범위를 기록에 표시해야 한다.
- 접근하지 못한 내용은 요약에서 제외하고 이유를 알려야 한다.
- AI는 원문에 없는 숫자, 인용, 출처를 생성해서는 안 된다.
- 사용자는 AI 정리를 수정하거나 다시 생성할 수 있어야 한다.

### 나만의 기록

- 저장 단계에서 자신의 기록을 생략할 수 있어야 한다.
- 텍스트와 음성으로 여러 시점의 생각을 추가할 수 있어야 한다.
- AI 작성 문장을 사용자 작성 문장처럼 표시해서는 안 된다.
- AI가 다듬은 경우에도 사용자의 최초 원문을 보존해야 한다.

### 분류와 연결

- 하나의 기록을 여러 주제에 연결할 수 있어야 한다.
- AI는 새 주제를 만들기 전에 기존 주제를 우선 추천해야 한다.
- 관련 기록 추천에는 연결 이유가 포함되어야 한다.
- 사용자는 추천 주제와 연결을 승인·거절·수정할 수 있어야 한다.

### 검색

- 원본 제목, 출처, AI 정리, 나만의 기록, 주제를 통합 검색해야 한다.
- 입력 유형이 달라도 같은 검색 결과에서 함께 보여야 한다.
- 검색 결과에서 AI 내용과 사용자 내용을 구분해야 한다.

### 알림

- 빈도, 요일, 시간과 유형을 변경할 수 있어야 한다.
- 오늘 기록을 완료하면 예정된 재촉 알림을 취소해야 한다.
- 알림을 누르면 해당 기록의 질문 화면으로 바로 이동해야 한다.
- 알림을 끄더라도 상시 기록 기능은 그대로 사용할 수 있어야 한다.

## 19. 개인정보·저작권·신뢰

- 사용자의 기록은 기본 비공개다.

- 사용자는 자신의 기록을 내보내고 삭제할 수 있다.
- 삭제된 기록은 일정 기간 복구할 수 있게 한 뒤 영구 삭제한다.

- 공유 메뉴 저장 시간 중앙값 10초 이하
- 원본 보존 성공률 95% 이상
- 저장 후 7일 안에 나만의 기록 추가율 40% 이상
- 질문형 알림 진입 후 기록 완료율 35% 이상
- 활성 사용자의 주간 과거 기록 재활용률 30% 이상

## 22. 검증 계획

### 사용자 인터뷰

- 콘텐츠를 주 5개 이상 저장하는 사용자 5명
- 현재 사용하는 저장 방법과 흩어진 장소 확인
- 다시 찾지 못했던 구체적인 경험 확인
- 한 줄 기록과 음성 기록의 부담 비교
- AI 요약과 나만의 기록 구분에 대한 이해 확인

### 사용성 과제

1. YouTube 앱에서 영상을 공유 메뉴로 저장한다.
2. 디자인 스크린샷을 저장하고 자동 기록을 확인한다.
3. 음성으로 나만의 생각 한 문장을 추가한다.
4. 일주일 전 저장한 기사를 검색한다.
5. 서로 다른 유형의 기록을 같은 주제로 연결한다.

### 우선 검증 가설

1. 입력 형식을 고르게 하지 않고 자동 판별하면 저장 시간이 줄어든다.
2. 저장 시 나만의 기록을 선택 사항으로 두면 저장 완료율이 높아진다.
3. 콘텐츠 제목이 들어간 질문형 알림이 일반 기록 알림보다 효과적이다.
4. AI 정리와 나만의 기록을 명확히 구분하면 서비스 신뢰도가 높아진다.
5. 과거 기록의 맥락 연결이 단순 재노출보다 활용 행동을 늘린다.

## 24. 포트폴리오 핵심 이야기

### 문제 정의의 변화

처음에는 링크를 요약하고 분류하는 서비스로 시작했다. 경쟁 서비스 조사와 사용자 관점 재검토를 통해, 진짜 문제는 요약이 아니라 다양한 정보를 자신의 생각으로 남기지 못하는 데 있다는 점을 발견했다.

### 주요 제품 결정

- 링크 요약에서 범용 입력 기록 서비스로 확장
- 모든 입력을 하나의 표준 기록 구조로 통합
- AI 자동 완성 대신 질문하는 AI 선택
- AI 정리와 사용자 생각의 명확한 분리
- 상시 기록을 핵심으로 하고 주 3회 알림은 보조 장치로 설계
- 저장 개수보다 재활용 기록 수를 핵심 지표로 선택

### 보여줄 산출물

- 문제 정의 변화 과정
- 경쟁 서비스와 차별화 분석
- 범용 입력 처리 구조
- 모바일 공유 메뉴 중심 사용자 여정
- AI 기록과 나만의 기록 정보 구조
- 질문형 알림 실험
- 사용성 테스트 전후 개선 결과
- 최종 모바일 앱 프로토타입
