# MEMOIVE 제작자 반복 사용 검증 계획

외부 테스트 참여자를 구하기 어려운 이번 주에는 제작자 1명이 실제 콘텐츠로 반복 사용합니다. 목적은 고객 수요를 입증하는 것이 아니라 핵심 흐름의 막힘과 개선 근거를 남기는 것입니다. 같은 사람이 5회 사용해도 참여자는 1명입니다.

## 검증할 가설

“저장할 때 내 생각을 남기면 시간이 지난 뒤 그 기록을 찾고 제안의 재료로 활용할 수 있다.” 아직 검증되지 않은 제품 가설입니다. 반복 테스트를 통해 기능적인 실현 가능성을 먼저 확인하고, 다른 사람에게도 유효한지는 제출 후 별도 조사합니다.

## 이번 주 진행 순서

1. 첫 회차에는 실제로 필요했던 콘텐츠 하나를 저장하고 생각을 남깁니다. 검색으로 다시 찾아 기획 제안 한 문단을 수정·저장합니다.
2. 최소 30분 뒤, 가능하면 다음 날 같은 기록을 다시 찾습니다. 제목을 외워 입력하지 말고 떠오르는 개념·생각을 사용합니다. 기다린 시간은 검색 수행 시간에 넣지 말고 완료 근거에 따로 적습니다.
3. 본문 읽기에 실패한 상황에서 주소와 메모가 남는지 확인합니다. 실패하지 않았다면 실패했다고 기록하지 않습니다. 확보한 본문을 텍스트로 옮겨 결과물까지 이어갈 수 있는지도 봅니다.
4. 반복해서 나타난 막힘 하나를 골라 수정하고, 바꾼 기능과 직접 관련된 과제를 다시 수행합니다. 변경 전후 버전과 사용한 콘텐츠가 다른 경우 그 차이를 명시합니다.

회차 수를 채우기 위해 같은 쉬운 자료만 반복하지 않습니다. 3~5회는 시작을 위한 제안이지 통계적 검증 기준이 아닙니다. 일부 회차는 평소 쓰던 메모앱·북마크로 수행해 볼 수 있지만 콘텐츠 난이도와 학습효과가 다르므로 시간 차이를 제품 효과라고 단정하지 않습니다.

## 기록 방법

MEMOIVE 상단 `내 기록 분석`에서 `내 사용 테스트`를 엽니다. 과제를 읽고 환경·버전을 적은 후 시간을 시작합니다. 새 탭의 앱에서 과제를 수행하고 돌아와 측정을 종료합니다. 이후 완료 여부·근거·막힌 점·다음 변경을 남깁니다.

개선 후 재시험이라면 `개선 후 다시 시험하나요?`에서 이전 회차를 고르고 실제 변경을 적습니다. 저장하면 이전에 막힌 점, 바꾼 내용, 두 회차의 결과·시간이 연결됩니다. 버전별 집계도 분리합니다. 비교는 원인 추정의 단서이며 조건이 다른 두 회차의 시간 차이를 개선 효과로 단정하지 않습니다.

타이머는 시작부터 종료까지의 실제 경과시간입니다. 앱 전환과 기다림도 포함되며 중간 일시정지 기능은 없습니다. 자리를 비웠다면 중단으로 기록합니다. 새로고침 이후에도 시작 시각이 유지됩니다.

## 완료와 지표의 정의

| 항목 | 판정 |
| --- | --- |
| 도움 없이 완료 | 해당 과제의 완료 기준을 모두 충족하고 외부 설명을 받지 않음 |
| 도움 후 완료 | 설명·힌트·직접 수정을 도움받은 뒤 완료 |
| 완료하지 못함 | 수행했으나 기준을 충족하지 못함 |
| 중단 | 중간에 수행을 멈춤 |
| 완료 시간 중앙값 | 같은 과제와 방식에서 도움 없이 완료한 회차의 시간만 정렬해 가운데 값 집계 |
| 결과물 활용 근거 | 저장한 결과물의 제목과 실제로 사용한 기록·문장을 남김. 생성 버튼만 누른 것은 활용 완료가 아님 |

앱의 `다시 본 기록` 비율은 저장 직후 자동 표시를 제외하고 상세를 직접 연 기록 수 ÷ 예시를 제외한 기록 수입니다. 며칠 뒤 재방문이나 고객 유지율이 아닙니다. 이벤트 보관은 최근 2,000개이므로 오래된 행동이 빠질 수 있습니다.

## 제출에 쓸 관찰

아직 관찰 결과는 없습니다. 실제 사용 후 다음 형식으로 본인의 판단을 적습니다.

“어떤 일을 하려 했는가 → 어느 화면에서 무엇이 막혔는가 → 왜 그 변경을 선택했는가 → 재시험에서 무엇이 달라졌는가 → 아직 모르는 것은 무엇인가.”

결과 파일은 JSON과 CSV로 내려받을 수 있습니다. 원본 메모는 비공개로 보관하고, 제출에는 개인정보를 제외한 요약만 사용합니다. 기술 점검을 수행한 AI의 입력이나 예시 자료를 제작자의 실제 경험으로 집계하지 않습니다.

## 다음 의사결정

- 기록 유실·잘못된 출처 연결은 다른 기능보다 먼저 고칩니다.
- 검색에 반복해서 실패한다면 검색어와 미발견 원인을 보고 단어 검색 개선 또는 의미 검색 도입을 검토합니다.
- 결과물을 거의 다시 쓰게 된다면 표현 기능을 추가하기 전에 목적·원문·내 의견 구분과 초안 구조를 먼저 고칩니다.
- 반복 사용 결과가 좋아도 수요를 입증했다고 하지 않습니다. 이후 처음 쓰는 대상 사용자에게 설명 없이 과제를 주고, 외부 검증 단계로 진행합니다.
