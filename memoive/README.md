# MEMOIVE — 영감을 결과물로 (제출 버전 v16)

흘러가는 정보를 영감으로, 영감을 결과물로.

MEMOIVE는 저장한 콘텐츠에 자신의 생각을 덧붙이고, 다시 찾아 실제 글이나 제안의 재료로 사용하는 모바일 중심 웹 시제품입니다. 이번 제출은 **콘텐츠 저장 → 내 생각 기록 → 재탐색 → 결과물 저장**의 한 흐름을 중심으로 설명합니다.

## v16: 기록 탐색과 하단 메뉴

문자 기호를 같은 선 굵기의 SVG 아이콘으로 교체했습니다. 선택 메뉴의 둥근 배경·밑줄·읽기 보조 상태와 큰 터치 영역, 하단 안전 여백을 유지합니다. 추가 라이브러리는 설치하지 않습니다.

홈·기록·검색·주제·달력·결과물 자료 선택은 저장 날짜 내림차순입니다. 새 기록은 저장 시각도 함께 보관해 같은 날짜에도 나중에 저장한 기록이 먼저 나옵니다. 시각 없는 이전 기록은 같은 날짜의 기존 순서를 유지합니다. 기존 중복 링크에 새 생각을 합치는 동작은 다시 저장한 시각으로 갱신됩니다. 원문 재읽기만으로는 순서가 바뀌지 않습니다. 정렬은 기록을 삭제하거나 내용을 변경하지 않습니다.

검사: `node tests/navigation-order-check.cjs`.

## v15: 세 사례로 보완한 흐름

홈의 **세 사례, 하나의 개선안**에서 토스·쏘카·무신사 예시를 읽고 **세 사례로 개선안 열기**를 누르면 편집 가능한 제안서 예시가 열립니다. 실시간 AI 생성이 아니라 원문을 읽고 미리 작성한 예시이며, 실제 사용자 성과를 담지 않습니다.

- [토스](https://toss.tech/article/undercover-silo-6): 작은 행동 실험에서 착안해 기록의 현재 상태와 다음 행동을 표시하고, 이미 저장한 결과물로 이어 쓰게 했습니다. 미션이나 횟수를 강제하지 않습니다.
- [쏘카](https://tech.socar.kr/product/2022/08/26/important-customer): 저장과 실제 활용을 나눕니다. 결과물 편집에서 선택적으로 사용 여부와 근거를 남깁니다. 이 사례의 지표는 저자의 개인 과제이며 회사 공식 지표가 아닙니다.
- [무신사](https://techblog.musinsa.com/무신사-메가스토어-성수-보이지-않는-기술-선명해지는-경험-a1976d599e83): 선택한 기록을 먼저 보여주고 나머지는 접어둡니다. 원문 접근 제한으로 사용자가 제공한 본문을 기준으로 정리했습니다.

세 예시의 **원문 요약 / 적용 아이디어(AI 제안) / 내 생각**을 구분합니다. 내 생각은 비워두며 기존 같은 주소의 기록과 생각은 덮어쓰지 않습니다. 기본 예시 5개와 추가 예시 3개, 예시만으로 만든 결과물은 실제 사용 집계에서 제외합니다.

**실제로 사용했다고 남긴 결과물**은 내 기록을 하나 이상 포함하고 사용 표시와 활용 근거가 있는 결과물 수(전체 기간, 현재 기기)입니다. 복사·다운로드·저장만으로는 늘어나지 않습니다. 체크를 취소하면 집계에서 빠집니다. 자기 보고이지 외부 검증이나 고객 전체의 성과가 아닙니다. 기존 브라우저 저장·백업 구조를 유지하며 계정 간 동기화는 추가하지 않았습니다.

추가 검사: `node tests/cases-use-check.cjs`. v14 공개 GitHub 반영은 PR #22에서 완료됐습니다. v15 사례 개선과 v16 메뉴·정렬 변경을 함께 후속 PR 대상으로 준비합니다.

## 해결하려는 문제와 초기 사용자

문제 가설은 “콘텐츠를 저장해도 저장한 이유를 잊고, 필요한 순간에 찾거나 실제 작업에 활용하기 어렵다”입니다. 초기 대상은 **제품 사례와 레퍼런스를 모아 기획안·포트폴리오를 만드는 PM/PO 및 컨설팅 직무 준비자**로 좁혔습니다. 제작자 본인의 관심과 실제 사용 맥락에서 출발한 선택이며, 인터뷰로 대표성이 확인된 집단은 아닙니다.

저장 개수보다 **내 생각을 남긴 기록을 다시 찾아 수정 가능한 결과물로 활용했는가**를 우선합니다. 북마크 목록만 제공하지 않고 기록과 결과물 사이의 연결을 보존하는 것이 제품 가설입니다. 경쟁 제품보다 우수하다는 검증은 아직 없습니다.

## 바로 실행하기

별도 설치 과정이나 API 키 없이 핵심 흐름을 사용할 수 있습니다. Python이 있는 환경에서 저장소를 내려받은 뒤 `memoive` 폴더를 열고 다음 명령을 실행합니다.

```sh
python -m http.server 4182 --directory .
```

브라우저에서 `http://localhost:4182/`를 엽니다. 모바일은 별도 배포 주소에서 사용합니다. 현재 운영 Site는 소유자만 접근할 수 있으므로 평가자에게 공개 시연 주소라고 안내하지 않습니다.

## 3분 시연 순서

1. `무엇이든 기록하기`에서 실제로 읽은 글을 텍스트로 입력합니다. 외부 서비스와 무관하게 재현할 수 있는 핵심 시연 경로입니다. 공개 기사 링크도 지원하지만 사이트 접근 제한에 따라 본문을 못 읽을 수 있습니다.
2. 저장 이유나 적용 아이디어를 `내 생각`에 적습니다.
3. 상세를 닫고 `기록`에서 제목 대신 생각의 핵심어를 검색합니다.
4. 찾은 기록에서 `결과물 만들기`를 선택합니다. `업무 제안서`를 고르고 전달 목적과 내 관점을 적습니다.
5. `기록으로 기본 초안 만들기`를 누르고, 나에게 맞게 문장을 고쳐 `나의 결과물로 저장`합니다.
6. 창작 메뉴에서 결과물을 다시 열고 참고 기록·내 생각을 확인합니다. 새로고침 뒤에도 글이 남는지 확인합니다.

기본 5개 예시는 화면 설명용입니다. 직접 입력한 기록이 아니며, 사용 성과 집계에서 제외합니다. 기술 테스트용 자료와 실제 사용 증거도 별도로 구분합니다.

## 현재 구현과 한계

| 영역 | 지금 실제로 하는 일 | 이번 제출에서 주장하지 않는 것 |
| --- | --- | --- |

| 정리 | 공개 본문에서 문장을 골라 정리, 사용자가 생각 추가 | 생성형 AI가 원문 전체를 이해하거나 사실을 검증했다는 주장 |
| 재탐색 | 제목·출처·주소·내 생각·핵심 문장·근거·주제의 단어 검색 | 의미 검색, 개인화 추천 모델 |

| 보존 | 같은 브라우저의 기기 저장, 앱 JSON 백업·합치기 | 계정 기반 클라우드 동기화, 영구 보관 보장 |
| 검증 | 제작자 반복 테스트 타이머, 결과·마찰·개선점 기록, JSON/CSV | 외부 사용자 검증, 고객 수요·효과 입증 |

기존 이미지·음성 입력과 공유 카드 기능은 유지했습니다. 그러나 이번 핵심 시연의 필수 범위는 텍스트와 공개 링크입니다. 기기별 녹음·문자 추출·공유 메뉴 동작은 별도 검증이 필요합니다.

## 검증 상태

실제 제작자 사용 결과는 아직 수집 전입니다. 임의의 성공률·만족도·시간 단축 수치를 넣지 않았습니다. 앱 분석의 숫자는 이 브라우저의 관찰일 뿐 제품 가치의 증명이 아닙니다.

```sh
node --check app.js
node --check self-test.js
node tests/submission-self-check.cjs
node tests/before-after-check.cjs
```

위 자동 점검은 검색, 예시 제외, 출처와 의견 분리, 테스트 집계·백업 병합 등의 기술 조건을 검사합니다. 사람의 사용성이나 초안 품질을 입증하지 않습니다. 화면 확인의 범위와 결과는 [기술 점검 범위](docs/verification.md)에 별도로 적습니다.

## 데이터와 외부 전송

- 앱 기록과 테스트 기록은 서로 다른 브라우저 보관 공간에 저장되며 각각 백업해야 합니다. 브라우저 데이터 삭제·기기 교체로 잃을 수 있습니다.
- 공개 링크를 읽을 때 해당 주소는 Jina AI Reader로 전송됩니다. 비공개 문서나 인증 정보가 포함된 URL을 넣지 마세요.
- Gemini는 현재 연결 전입니다. 이후 연결 시 선택한 기록과 내 생각을 외부 AI로 전송하기 전 안내·동의와 서버의 접근 제어를 점검해야 합니다.
- 테스트 메모와 백업 파일은 GitHub에 자동 전송하지 않습니다. 공개할 근거는 개인정보와 비공개 원문을 제외해 따로 정리합니다.
